# Workshop · LedgerLine LIFF Mobile Admin Console

> Generated by `/feature-workshop` (4 personas) on 2026-06-05 · Status: **Approved** (CEO `/goal` "ทำทั้งหมด ให้ใช้ได้จริงสมบูรณ์ทุกขั้นตอน")
> Repo: pooilgroup-web (module `ledger`). Built on the live LedgerLine (setup 37e50d6).

## 1. 🎯 Goal & Success Metrics
- **เป้าหมาย:** ยกหน้าจัดการ/ตั้งค่าทั้งหมดของ LedgerLine มาทำงานได้ 100% บนมือถือผ่าน LINE LIFF เลียนแบบ UX ของ Bainy — แอดมินทำทุกอย่าง (เชิญ/อนุมัติคน · เพิ่มสาขา · กำหนดสิทธิ์ · เพิ่มหมวด · แก้องค์กร) จบในมือถือ ไม่ต้องเปิดคอม.
- **Success metric (หลัก):** mobile coverage = ทุก settings task ที่ทำบนเว็บได้ ต้องทำบน LIFF console ได้ + เพิ่มสาขา/อนุมัติคน < 2 นาทีจากมือถือ.
- **DoD:** เปิด LIFF console จาก Rich Menu → ผ่าน gate → ทุก tab โหลด+กดได้จริง (ไม่มี dead UI) · ทุก action verify ฝั่ง server · tsc 0 · build เขียว · ไม่มี P&L leak · audit ผ่าน.

## 2. 👥 User Personas
- **CEO/เจ้าของ** (primary admin, iPhone) — จัดการทุกบริษัทใน JP Sync. ใช้แบบ bursty (ตอน onboard สาขา/คนใหม่).
- **บัญชีกลาง 1-2 คน** (accountant) — ยืนยันบิล · export · อนุมัติคำขอสาขาแทนได้.
- **พนักงานสาขา** (staff) — ส่งใบเสร็จ/จด (ไม่เข้า console — กดเจอจอ "เฉพาะผู้ดูแล").
- **สำนักงานบัญชีภายนอก** (external_accountant) — ดู + export อย่างเดียว.

## 3. 🚶 User Journey
Rich Menu "จัดการทีม" → LIFF เปิด `/liff/ledger/admin` → LiffBootstrap auth (LINE id_token) → server verify → ถ้าไม่ใช่แอดมิน: จอ "เฉพาะผู้ดูแล" + ปุ่มกลับถ่ายใบเสร็จ → ถ้าใช่: console (header เหนียว: บริษัทปัจจุบัน + banner "รออนุมัติ N") + bottom-nav. แตะ tab → จัดการ → action → server re-verify id_token → "บันทึกแล้ว".

## 4. ✅ Feature List (MoSCoW) — CEO: ทำทั้งหมด
**Must-have (v1):**
- LIFF console shell mirror Bainy: tab [องค์กร · สาขา · สมาชิก · สิทธิ์ · ตั้งค่า] (top) + bottom-nav, mobile-first.
- Gate screen (admin only) + entry via Rich Menu "จัดการทีม".
- **สมาชิก**: list (active only) · bottom-sheet edit (role + สาขา multi-select + active) · approve/reject pending **2-step** confirm.
- **เชิญ**: create scoped invite link + แชร์เข้า LINE · revoke.
- **สิทธิ์**: 4 roles (staff/accountant/admin/external_accountant) · เปิด-ปิด **money-capabilities** 5 อัน (confirm→post · export · view-P&L · all-branches · edit/delete-others) ต่อ role · ภาษาคน.
- **ประเภท** (category): CRUD หมวดค่าใช้จ่าย.
- **องค์กร**: แก้ข้อมูลบริษัท (ชื่อ TH/EN · Tax ID · VAT · ที่อยู่).
- **สาขา**: CRUD + **คำเตือนชัดว่ากระทบทุกโมดูล** (shared Pool Branch).
- **ตั้งค่า**: ผูก LINE OA + branch · ติดตั้ง Rich Menu · export config.
- **Auth (hybrid)**: id_token verify per-action; linked Pool user → Pool path; กันข้ามบริษัท + audit.
- **Permission enforcement**: `can(role, capability)` helper จุดเดียว ใช้ทั้ง LIFF action + LINE command + web action (เรื่องเงิน).
- **PDPA**: แสดงเฉพาะ active member + ปุ่มลบ/ปิด.

**Should-have:** LINE↔Pool self-link flow (admin ผูกบัญชีเองได้ง่าย) · per-member capability override.
**Could-have (v2):** full per-action matrix · org-switch UX polish · audit-log viewer.
**Won't (v1):** billing/upgrade · self-signup · edit-delete expense ในแชต · auto-post TRCloud.

```mermaid

  ledger_line_member { uuid id PK; uuid orgId; uuid companyId; string lineUserId; uuid poolUserId "nullable"; string role "staff|accountant|admin|external_accountant"; uuid[] scopeBranchIds; uuid pendingBranchId; bool active }

  ledger_line_member ||--o{ Branch : "scope"
```
- **NEW** `ledger_permission` (orgId × role × capability → allowed) · `@@unique([orgId, role, capability])`. Seed Bainy-style defaults.
- **EXTEND** `ledger_line_member.role` → allow `external_accountant`.
- Capabilities (5): `expense.confirm`, `expense.export`, `report.view_pnl`, `scope.all_branches`, `expense.edit_others`.

## 6. 🔌 Integration Points
- LINE LIFF (LedgerLine channel `2010283514-MjoaxJe4`) → `/liff/ledger/admin`. Auth = LiffBootstrap → `/api/auth/line-login` (verify id_token vs ledger login channel) → Pool session for linked users.
- **iOS cookie-drop mitigation:** every admin write action re-verifies a fresh LINE id_token server-side (not cookie-only) + explicit "บันทึกแล้ว" read-back.
- Branch/Company = shared Pool core entities (touched by chairops/clawfleet/fuel) → CRUD shows cross-module warning.

## 7. 🚨 Edge Cases
1. ไม่ใช่แอดมินเปิด console → จอ "เฉพาะผู้ดูแล".  2. iOS cookie หลุดกลาง write → re-verify id_token, ไม่เขียนเงียบ.  3. แก้สิทธิ์ชนกัน 2 คน → optimistic (เทียบ updatedAt) เตือน ไม่ทับเงียบ + audit.  4. ลบหมวดที่มี expense → บล็อก "มี N รายการ ย้ายก่อน".  5. ลบ/แก้สาขาที่โมดูลอื่นใช้ → เตือน.  6. auto-seeded member ห้ามเป็น admin อัตโนมัติ.  7. invite role=admin → ต้องอนุมัติ/ยืนยัน.  8. กด approve ผิด (จอเล็ก) → 2-step.  9. P&L ตอบเฉพาะ registered group/admin.  10. unlinked admin (poolUserId null) → audit เก็บ actorLineUserId.

## 9. ⚠️ Risks (Top 5)
1. **Authz divergence (2 role systems)** → security helper จุดเดียว + Pool role ยังคุม cross-module/org · ledger role คุมเฉพาะ ledger.  2. **RLS-bypass บน LINE-id path** → ทุก query scope orgId+companyId explicit.  3. **iOS cookie-drop บน write** → id_token re-verify per action.  4. **Branch CRUD กระทบ shared data** → warn + จำกัด field.  5. **Over-build permission** → จำกัดที่ 5 money-capabilities เท่านั้น.
