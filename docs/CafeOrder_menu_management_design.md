## 0. สรุปสำหรับ CEO (อ่านจบใน 1 นาที)

**ร้านจัดการเมนูเองได้ 100% ไม่ต้องเรียกโปรแกรมเมอร์** — เพิ่ม/แก้/ลบเมนู · อัปรูป · ตั้งราคา · เปิด-ปิดขาย · ตั้งตัวเลือก (หวาน/น้ำแข็ง/ท็อปปิ้ง/ขนาด) ทุกอย่างผ่านหน้าเว็บ

**2 วิธีเพิ่มเมนู:**
1. **ทีละรายการ** — กดปุ่ม "เพิ่มเมนู" กรอกในฟอร์ม อัปรูป เสร็จ
2. **ทีเดียวเป็นร้อย** — โหลด template Excel → กรอก/วางในไฟล์ → อัปกลับ → ระบบพรีวิวให้ดูก่อน → กดยืนยัน เข้าทั้งหมด

**หัวใจที่ทำให้ไม่เหนื่อย (หลายสาขา):** เมนูทำ **"ที่เดียวใช้ทุกสาขา"** — พี่ตั้งเมนูกลางของ Amazon / พันธุ์ไทย ครั้งเดียว ทุกสาขาได้เหมือนกันหมด · แต่ละสาขาแค่ **กดเปิด-ปิด** ว่าขายอะไร + **แก้ราคาเฉพาะสาขา** ถ้าต่างกัน + **กด "วันนี้หมด"** ตอนของหมด · **ไม่ต้องคีย์เมนู 80 รายการ × ทุกสาขา** (นี่คือกับดักที่ FoodStory ขายเป็นฟีเจอร์เรือธง — เราเลี่ยงตั้งแต่วันแรก)

**เราเติมเมนูจริงให้พี่ไว้ก่อนแล้ว** — พันธุ์ไทย 48 + Amazon 70 เมนู (จาก research) โหลดเข้าเป็นตัวตั้งต้น พี่แค่แก้ราคาให้ตรงสาขา ไม่ต้องเริ่มจากศูนย์

## 1. โครงข้อมูล (data model) — 2 ชั้น: กลาง + รายสาขา

```
┌─────────────────── ชั้นกลาง (ตั้งครั้งเดียว ต่อแบรนด์) ───────────────────┐
│                                                                          │
│  cafe_categories        หมวด (กาแฟ/ชา/ปั่น/เบเกอรี) · ลำดับ               │
│                                                                          │
│  cafe_menu_items        เมนูหลัก                                          │
│    id · brand(amazon/punthai) · categoryId · name · description          │
│    · imageKey (R2) · kind(drink/food) · isActive · sortOrder             │
│                                                                          │
│  cafe_item_variants     ★ ราคาต่อ "อุณหภูมิ × ขนาด" (รองรับขนาด)          │
│    itemId · temp(hot/iced/blended) · size(regular/large)                 │
│    · priceCents · isActive                                               │
│    (เช่น ลาเต้: hot-reg 55 · hot-large 65 · iced-reg 70 · blended 75)     │
│                                                                          │
│  cafe_option_groups     กลุ่มตัวเลือก (preset + สร้างเอง)                 │
│    id · brand/global · name · minSelect · maxSelect · required           │
│    · visibleWhenTemp (null=ทุกแบบ / iced=เฉพาะเย็น) ← ซ่อนน้ำแข็งตอนร้อน   │
│                                                                          │
│  cafe_option_choices    ตัวเลือกในกลุ่ม + ราคาเพิ่ม                        │
│    groupId · label · priceDeltaCents · isActive · sortOrder              │
│                                                                          │
│  cafe_item_option_groups   เมนูไหนใช้กลุ่มไหน (many-to-many)              │
│    itemId · optionGroupId · sortOrder                                    │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
              │ inherit ↓ (ทุกสาขาได้เมนูกลางอัตโนมัติ)
┌─────────────────── ชั้นสาขา (แต่ละสาขา override เท่าที่ต่าง) ───────────────┐
│                                                                          │
│  cafe_branch_items      สาขานี้ขายเมนูนี้ไหม + ราคาเฉพาะสาขา              │
│    branchId · itemId · isAvailable · priceOverrideCents(null=ใช้กลาง)     │
│    · soldOutUntil(null=มีของ) ← ปุ่ม "วันนี้หมด" reset เที่ยงคืน           │
│                                                                          │
│  cafe_branch_choice_stock   ตัวเลือกหมดเฉพาะสาขา (นมโอ๊ตหมด)              │
│    branchId · optionChoiceId · soldOutUntil                              │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

**เหตุผลออกแบบ 2 ชั้น** (ตรงกับ [feedback-void-bill-blocks-reissue-unique-slot] + research FoodStory Master Data):
- เพิ่มเมนูใหม่ = insert แถวเดียวในชั้นกลาง → 118 สาขาเห็นทันที
- ปิด/เปิด/แก้ราคาเฉพาะสาขา = แตะแค่ `cafe_branch_items` ไม่กระทบสาขาอื่น
- `@@schema("cafeorder")` ทุกตาราง · orgId/branchId = plain `@db.Uuid` (ตาม prisma/schema.prisma:7831 pattern) · **หลีกชื่อ `Order` ที่ FuelOS จองแล้ว** (prisma/schema.prisma:6012) → ใช้ prefix `Cafe*`

## 3. นำเข้าทีละหลายรายการ (bulk import) + template

**Flow (ยืมจาก ChairOps/CashHub import ที่มีอยู่):**
```
[⬇ โหลด template]  →  กรอกใน Excel  →  [⬆ อัปไฟล์]  →  พรีวิว  →  [ยืนยัน]  →  เข้าระบบ  →  [เลิกทำ]
                                                    │
                          ┌─────────────────────────┴──────────────────────────┐
                          │ พรีวิวโชว์:  ✅ เพิ่มใหม่ 42   ✏️ อัปเดต 6   ⏭ ข้าม 2  │
                          │             🔴 ผิด 1 แถว (แถว 15 ราคาเป็นตัวอักษร)     │
                          │ ✋ ผิด = บล็อกเฉพาะแถวนั้น ไม่ล้มทั้งไฟล์               │
                          └────────────────────────────────────────────────────┘
```

**Upsert key** = `brand + ชื่อเมนู` (หรือคอลัมน์ SKU ถ้ากรอก) → มีอยู่แล้ว = อัปเดต · ไม่มี = สร้างใหม่ · **ไม่สร้างซ้ำ**

**ยืม/สร้างใหม่:**
| ต้องมี | ของเดิม (file:line) | หมายเหตุ |
|---|---|---|
| lib อ่าน/เขียน Excel | `xlsx ^0.18.5` (package.json — มีแล้ว) | ไม่ต้องลง lib ใหม่ |
| สร้างไฟล์ template ให้โหลด | `app/api/chairops/import/maid-collections/template/route.ts` | ยืม pattern → `app/api/cafeorder/menu/template/route.ts` |
| parse xlsx | `lib/chairops/pos-ingest/starthing-xlsx.ts` · `lib/cashhub/fuel-parser.ts` | ยืม pattern |
| พรีวิวก่อนบันทึก | `app/api/cashhub/amazon-import/preview/route.ts` | ยืม pattern (preview→confirm) |
| กันกดยืนยันซ้ำ/ปลอมแปลง | HMAC payload (แบบ ClawFleet import · env `CAFEORDER_IMPORT_PAYLOAD_SECRET`) | ต้องมี idempotency **จริง** (unique index) ไม่ใช่ helper ปลอม — ดู [fake-safety-idempotency-helper-no-db-column] |

**Template = Excel 3 แท็บ** (ตัวอย่างสร้างไว้แล้ว 2 ไฟล์ CSV):
- **แท็บ 1 · เมนู** → `docs/CafeOrder_menu_import_template.csv` (กรอกเมนู + ราคาตามแบบ + ขนาด + รูป URL + กลุ่มตัวเลือก)
- **แท็บ 2 · ตัวเลือก (presets)** → `docs/CafeOrder_menu_import_optiongroups.csv` (หวาน/น้ำแข็ง/ท็อปปิ้ง/ช็อต/นม พร้อมราคา — แก้ได้)
- **แท็บ 3 · วิธีกรอก** (คำอธิบายในไฟล์จริง)

### รูปในการ import (ตอบโจทย์ "เพิ่มรูป")
- **คอลัมน์ `รูป_URL`** ในแท็บ 1 — วาง URL รูปได้เลย (เรามี URL รูปบางส่วนจาก research อยู่แล้ว → เติมให้ได้)
- หรืออัปรูปทีหลังทีละเมนูในหน้าจัดการ (ปุ่มกล้อง/อัปโหลด)
- **อัปรูปหลายรูปพร้อมกันแล้วจับคู่อัตโนมัติ (ตั้งชื่อไฟล์ = SKU)** = ทำได้ แต่ขอไว้ v2 (import รอบแรกใช้ URL/ทีละรูปก่อน)
