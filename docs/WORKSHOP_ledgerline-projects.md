## 3. 🗣️ Debate Highlights (สิ่งที่ทีมเถียงกันจริง)

1. **F1 เป็นแค่ "ขัดเงา" หรือมีบั๊กจริง?** — PM/Programmer/Devil/Owner เชียร์ว่า F1 แค่เช็ก config + polish (ฟังก์ชันมีครบใน LIFF แล้ว). **Verifier แย้งด้วยโค้ดจริง: มีบั๊กจริง** — invite แบบพนักงาน (`kind='member'`) ไม่ผูก `users.line_login_sub` → `resolveLedgerActor` หาไม่เจอตอนกลับเข้ามา → **พนักงานติดหน้า "บัญชียังไม่เปิดใช้งาน" ทั้งที่เพิ่งกดเข้าร่วมสำเร็จ**. สรุป: F1 = verify + **แก้บั๊ก 1 จุด (ต้องแก้โค้ด)** + polish หน้า error

2. **F2 "โครงการ" = แฮ็กชื่อ category (0 migration) หรือ column ใหม่จริง?** — Devil ดันหนักว่าใช้ชื่อ category "โครงการ: ตึก A" ไปก่อน. ทีมค้านเป็นเอกฉันท์ + verifier ยืนยัน: `LedgerCategory` มี `trcloudAccCode/trcloudProductCode/vatClaimable` = **มันคือผัง GL/SKU** → แฮ็กชื่อ = ทำ chart-of-accounts พังทางอ้อม + ชนคีย์ LedgerBudget. **สรุป: ทำ `projectId` FK + ตาราง `LedgerProject` จริง** (ถูก+ปลอดภัย+ย้อนกลับได้) แต่ Owner รับวินัย Devil ที่ว่า "พิสูจน์ว่ามีคนใช้ก่อน" → ทำ schema ครั้งเดียวให้ถูก แต่ค่อยลงแรงทำรายงานเต็มเมื่อเห็นการติดป้ายจริง

3. **งวด "จ่ายแล้ว" ยึดกับอะไร?** — เกือบทุกที่นั่งบอกยึด `paidExpenseId`. SA แย้งตัวเองรอบ 2: สลิปจริงอยู่บน `LedgerPayment.slipUrl` ผ่าน `LedgerPaymentRequest` (ขอโอน) ต่างหาก. **สรุป (verifier หนุน): ยึด `paidPaymentRequestId` เป็นหลัก** (ได้สลิปจริงมาโชว์ฟรี ไม่ต้องอัปใหม่) + `paidExpenseId` เป็น fallback เงินสด

4. **งวดต้องแยกตามผู้รับเหมาไหม?** — ผจก.ก่อสร้าง+End User: reno จริงจ่ายหลายเจ้า (รับเหมาหลัก+ช่างสี+ช่างไฟ) คนละ WHT. PM/UX/Architect ค้านว่าเกิน LIGHT. **สรุป: มีช่อง `vendorLabel` (free-text) ต่องวด** — ไม่มีตาราง master ผู้รับเหมา ไม่มี rollup ต่อเจ้า (Phase 2)

5. **รายงานต้นทุนโครงการ = เลขเดียว หรือ 3 เลขซ้อน? เทียบงบด้วยเลขไหน?** — นักบัญชีเสนอ 3 เลข (ต้นทุนสุทธิ/VAT ซื้อ/จ่ายจริง) แล้วแก้ตัวเองว่า 3 เลขเท่ากันทำ CEO งง. **สรุป: พาดหัวเลขเดียว = ต้นทุนสุทธิ (subtotal) + ลิ้นชักภาษีพับเก็บ** · header เขียน "มุมมองบริหาร — ไม่ใช่บัญชีตามงบ" · **แต่ "เทียบงบด้วยเลขไหน" ยังไม่ล็อก → CEO เคาะ (§7 Q2)**

6. **ปิดงวด "จ่ายแล้ว" ต้องมีสลิปก่อนไหม?** — นักบัญชี/PM: บังคับมีบิลก่อน. End User/หัวหน้างาน: หน้างานจ่ายเงินสดก่อน สลิปมาทีหลัง. **สรุป (โน้มไป): มีสถานะเหลือง "จ่ายแล้ว—รอสลิป" → เขียวเมื่อผูกสลิปจริง** · budget-vs-actual ที่เชื่อได้นับเฉพาะเขียว → **CEO เคาะ (§7 Q3)**

7. **งวดใช้ตาราง payment-request เดิม หรือทำใหม่?** — **สรุป hybrid: ตาราง `LedgerInstallment` ใหม่ (plan-row) แต่จ่ายผ่าน `createPaymentRequest` เดิมไม่แก้** → ได้ตัวกันจ่ายซ้ำ (transRef/partial-unique) + สลิปฟรี · เพิ่ม partial-unique กันมาร์คจ่ายซ้ำ

## 4. ✅ Consensus Decisions

- **F1** = verify + แก้บั๊ก identity-binding 1 จุด + ขัดหน้า error (ไม่ใช่สร้างใหม่)
- **F2 "project"** = มิติ display/report แนวขวาง (เหมือน branchId/categoryId) · **ห้าม fork ผัง GL · ห้ามดัน TRCloud · ห้ามแตะ confirm/ขอโอน**
- **ติดป้ายโครงการ** = chip 1 แตะ ไม่บังคับ จำโครงการล่าสุด (web + LIFF) · reuse `SearchableSelect`
- **งวด** = plan-row (`LedgerInstallment`) มี status ของตัวเอง · **ห้ามเขียน `expense.paymentStatus`** (default 'paid' เชื่อไม่ได้) · จ่ายผ่าน money path เดียวเดิม
- **สิทธิ์**: reuse `can()`/`ledgerWebCanForRole` เพิ่มแค่ 1 capability `project.manage` (สร้าง/ปิดโครงการ + จัดงวด) · ติดป้าย = ใช้ gate `expense.edit_others`/own-row เดิม
- **LIFF ทุก write** re-verify ผ่าน `resolveLedgerActor` เสมอ (ห้ามเชื่อ cookie)
- **ลบโครงการ = soft-archive** เท่านั้น (FK RESTRICT/SetNull ห้าม cascade) · รายงานย้อนหลังต้องยังเปิดได้
- **ทุก query F2/F3** กรอง `orgId` **และ** `companyId` + มี seed test Pooil≠JPS เป็น acceptance
- **ลำดับ FK บังคับ:** F1 → F2 → F3 (งวด `projectId NOT NULL` → เกิดก่อนตารางโครงการไม่ได้)
- **UI reuse kit เดิม 100%** ไม่มี component family ใหม่ ไม่มีสีต่อโครงการ (แบรนด์น้ำเงินเดียว)

## 6. 🧩 Feature Spec (MoSCoW)

### MUST
- **F1 บั๊กชั้น 1 (เข้าไม่ได้):** invite `kind='member'` → มินต์ Pool user เบา + bind `users.line_login_sub` (มิเรอร์ `admin_claim` / `ensureLedgerAdminPoolUser`) ที่ `accept/route.ts` หลังบรรทัด 131 → `resolveLedgerActor` เจอตอนกลับเข้ามา
- **F1 บั๊กชั้น 2 (เห็นแต่กดขอโอนไม่ได้ · verified 2026-07-09):** ปุ่มขอโอนบน LIFF (`app/liff/ledger/expense/[id]/page.tsx:114`) ใช้ `ledgerWebCanForRole(orgId, session.user.role, "payment.request")` = **Pool role** → staff/member ได้ `false` (liff-auth.ts:150 ผ่านเฉพาะ admin-tier+viewer) → **พนักงานไม่เห็นปุ่ม** ทั้งที่ matrix เปิดให้ staff ✅. FIX: เปลี่ยนเป็น `ledgerWebCan(actor, "payment.request")` โดยใช้ **ledger member role จาก `resolveLedgerActor`** (server action `createPaymentRequestAction` _actions.ts:3083 ใช้ gate เดียวกัน → แก้คู่กัน). ผลลัพธ์: พนักงานถ่ายใบเสร็จขอโอนในไลน์ได้จริง (เป้าหมายแท้ของ F1)
- **F1** เช็ก `NEXT_PUBLIC_LEDGER_LIFF_ID` + LEDGER LOGIN channel id ตั้งใน prod (ไม่มี = block onboarding ทั้งหมด) + **cold-device walk** (invite→join→accept→my→edit→ขอโอน) บนไลน์ user ใหม่ **0 ครั้ง 403** = acceptance gate
- **F1** ทุกหน้า fail (หมดอายุ/ใช้แล้ว/channel ผิด/timeout/เปิดนอกไลน์/ยังไม่ล็อกอินไลน์) = ข้อความไทยชัด + ปุ่มเดียว ไม่มีจอเปล่า/403 ดิบ
- **F2** `projectId` FK (SetNull) + `LedgerProject` + ร้อยผ่าน `buildWhere` **และ** `baseWhere` · migration **APPLIED in prod**
- **F2** chip "โครงการ" 1 แตะ ไม่บังคับ จำล่าสุด (web+LIFF) · reuse `SearchableSelect`
- **F2** รายงานต้นทุน 1 หน้า · พาดหัว = **ต้นทุนสุทธิ (subtotal)** · header "มุมมองบริหาร — ไม่ใช่บัญชีตามงบ" · เทียบงบด้วย basis ที่ **ปักธง+ติดป้ายชัด** (Q2)
- **F2 (critic)** ปักกฎ: รายงานรวม **status เดียวกับ ledger (`confirmed`+`locked`)** + โชว์บรรทัดแยก "รอตรวจ N รายการ (฿X)" สำหรับที่ติดป้ายแต่ยัง draft → acceptance: รวม+รอตรวจ = Σ ทุกแถวที่ติดป้าย
- **F3** `LedgerInstallment` (`projectId NOT NULL`) มี status เอง · จ่ายแล้ว **ต้องผูก `paidPaymentRequestId`** (หรือ `paidExpenseId` เงินสด) · **ห้ามเขียน `expense.paymentStatus`**
- **F3** mark-paid reuse money path เดิม · งวดจ่ายแล้วโชว์ `ReceiptThumb` สลิปจริง (ไม่มีเขียวไร้หลักฐาน)
- **F3 (critic — ช่องโหว่ใหญ่สุด) WHT:** `plannedAmount` = **ยอดสัญญาเต็ม (gross)** · แถวโชว์ 2 เลข: "ยอดสัญญา" (gross) + "โอนจริง" (`expectedTransfer = gross−WHT 3%` จาก `LedgerPaymentRequest`) · **ช่องว่าง WHT 3% = คาดไว้ ไม่ใช่ underpaid/สลิปหลุด** — ไม่งั้นงวดก่อสร้างทุกงวดขึ้นแดงหลอก (ทับ VAT ~7% เป็น ~10%)
- **F3 (critic) mobile-first:** mark-paid picker บน LIFF = bottom-sheet (search + จำนวน + thumb ต่อแถว · reuse pattern 1688) · รายงานต้นทุนย่อเป็น single-column card ที่ 375px ลิ้นชักภาษีเป็นแถวกาง
- **ALL** ทุก query กรอง orgId+companyId + seed test Pooil≠JPS **ต่อ aggregator** · ลบโครงการ = soft-archive/RESTRICT · reuse `can()`/`resolveLedgerActor` +≤1 capability · LIFF write re-verify actor
- **(critic) quick-create-project idempotent:** upsert บน (orgId,companyId, normalized name) — ชนแล้วคืนตัวเดิม ห้าม 500 (RULE I race guard)

### MUST (เพิ่มจาก CEO decision)
- **F3 งวด 3 สถานะ (CEO #3 locked):** planned / **amber "จ่ายแล้ว—รอสลิป"** (แก้จาก LIFF ได้) / เขียว(ผูกสลิปแล้ว) + broken "สลิปหลุด" · budget-vs-actual นับเฉพาะเขียว · amber โชว์แยก
