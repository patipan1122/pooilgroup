FuelOS — รายงานประชุมทีม

ระบบขายส่งน้ำมัน (standalone) · 1 มิ.ย. 2026

🧭 ภาพรวมการประชุม

ทีม 13 บทบาทเห็นตรงกันชัดเจนว่า "หัวใจจริง" ของ FuelOS คือ F1+F2+F3+F7 (กล่องแชทกลุ่ม LINE + รู้ว่าใครตอบ/ค้างตอบ + KPI + ราคาเช้าอัตโนมัติ) ส่วน F11 (บัญชีเต็มรูป) และ route optimization ใน F10 ถูกตีว่า over-scope รุนแรง ควรตัดออกจากเฟสแรก. ความเสี่ยงเทคนิคอันดับ 1 ที่ยังไม่มีใครพิสูจน์คือ "LINE OA จะเห็นข้อความที่พนักงาน/ลูกค้าพิมพ์กันเองในกลุ่มครบไหม" — ถ้าเห็นไม่ครบ F2/F3 ตายทั้งคู่ และทั้งโปรเจกต์เสียเหตุผลหลัก จึงควรทำ PoC 1 กลุ่มจริงก่อนลงทุนสร้างทั้งระบบ. โค้ดต้นแบบ Inbox รับแค่ 1:1 ยังไม่รับกลุ่ม + assignedToId/contactPhone เป็น field ลอยไม่มี relation + ขาดตาราง map LINE userId พนักงาน ทำให้ "ประตูหน้า" ต้อง redesign ไม่ใช่ก๊อปแล้วใช้เลย. แนะนำลำดับ: พิสูจน์เทคนิค → ship F1+F2+F7 ใน ~2 สัปดาห์ → ค่อยต่อ F3/F5/F6/F8 → เลื่อน F4(บอทในกลุ่ม)/F9/F10/F11 เป็นคลื่นถัดไป.

📋 รีวิวรายฟีเจอร์ (F1–F12)

F1 กล่องรวมแชท LINE (OA+กลุ่ม) = ประตูหน้าmust-have (ทำก่อนสุด แต่ redesign ไม่ใช่ก๊อป)

ทุก persona ยกเป็นหัวใจ ROI สูงสุด — ลูกค้าน้ำมันสั่งของ/ส่งสลิป/ถามราคาในกลุ่ม LINE 30+ กลุ่มแล้วตกหล่น = เสียยอดตรง. แต่โค้ด Inbox เดิมรับแค่ 1:1 (อ่าน source.userId, drop event ที่ไม่มี userId, unique key [channelId,externalUserId]) ต้อง refactor: เพิ่ม groupId + conversationType(USER|GROUP) + เก็บผู้พูดราย message. ⚠️ ยังไม่มีใครพิสูจน์ว่า OA เห็นข้อความในกลุ่มครบ — ต้อง PoC ก่อน. NO backfill ประวัติเก่า ต้อง set expectation วันแรกระบบว่างเปล่า

F2 ใครตอบ/ค้างตอบ + assigneemust-have (คู่กับ F1)

แก้ pain หัวหน้า 'ไม่รู้ใครดูแลเจ้าไหน เงียบก็ไม่รู้'. แต่ assignedToId เป็น field ลอย 0 callers ไม่มี relation/UI ต้องสร้างใหม่. ปัญหารากคือพนักงานตอบจาก LINE ส่วนตัวในกลุ่ม → รู้ 'ใครตอบ' ได้ต่อเมื่อ map LINE userId พนักงานครบทุกคน (ต้องเพิ่มตาราง StaffLineIdentity + flow onboarding). ถ้า map ไม่ครบ KPI เพี้ยน โทษผิดคน

F3 รายงาน/KPI เวลาตอบ-ตกหล่น-รายคนmust-have แต่ระวัง (นิยามต้องล็อกก่อนเก็บข้อมูล)

ตรงคำขอ CEO 'ตั้ง+วัด KPI'. schema LineResponseLog มี field พร้อม แต่ไม่ wire เข้า inbox = ตารางเปล่า + แยกขาดจาก InboxMessage (เสี่ยง 2 source of truth). ความเสี่ยงใหญ่: KPI หลอกตัวเอง — เซลล์กด 'รับทราบ' หยุดนาฬิกาแต่ไม่แก้, ดีลปิดทางโทร undercount, นับ burst/นอกเวลาทำการ. ต้องนิยาม working-hours + 'ตอบจริง' ก่อน ไม่งั้นการเมืองในทีม

F4 บอท AI ช่วยตอบ+escalate+สรุปวันทำทีหลัง + ระวัง

engine reuse ได้ (FAQ→AI→escalate + businessTag pooil + daily summary). แต่บอทในกลุ่มที่มีลูกค้าหลายเจ้าเสี่ยงตอบทับคน/ตอบราคาผิด = เสียเงินจริง (margin น้ำมันบาง). แนะนำเริ่มแบบ 'บอทเสนอคำตอบให้เซลล์กดส่ง' ไม่ auto-reply ในกลุ่ม + guard ดึงราคาจาก DB เท่านั้น + loop-guard + cost-cap ต่อวัน. หลายคนแนะให้เลื่อนหลังพิสูจน์ F1-F3

F5 CRM ก้าวกระโดด full supportทำทีหลัง (MVP แค่ผูกแชท↔ลูกค้า อย่าทำ full)

'full support' = red flag scope ไม่จำกัด. schema 3 ชั้น (Contact→CustomerEntity→DeliveryLocation) ออกแบบดี แต่ conversation ไม่มี contactId FK (มีแค่ phone/note string ลอย). MVP ควรแค่: ผูก conversation↔Contact + auto-match by lineUserId + ดูประวัติ. ธุรกิจน้ำมันลูกค้า 50-300 ราย ไม่ต้องการ CRM แบบ Salesforce

F6 ออกใบเสนอราคา/ออเดอร์จากแชททำทีหลัง (พึ่ง F5+F7+F8)

'wow feature' ลดขั้นตอนตามที่ CEO ขอ. CustomerQuote/FuelOrder มี source field พร้อม. แต่ FuelOrder บังคับ FK entityId+locationId NOT NULL → ลูกค้าใหม่/จุดส่งใหม่ออกไม่ได้ flow กลายเป็น 8-10 คลิกแทน 2-3. ต้อง progressive: ออกใบราคาเบาได้เลย แปลงเป็นออเดอร์ค่อยบังคับกรอก + เช็คเครดิตตอนแปลง

F7 ราคาคลังเช้า + margin โซน → ราคาขายอัตโนมัติmust-have (quick win ทำเร็วที่สุด ROI สูงสุดต่อแรง)

standalone ไม่ติด LINE ทำได้เลย. DepotPrice+ZoneMargin schema พร้อม + minMargin กันตัดราคา. แก้ pain 'เซลล์ขายราคาคนละราคา/ขายต่ำกว่าทุน'. ⚠️ valid_until เป็น string HH:mm ไม่มี timezone/วันที่ = bug รอเกิด. ต้อง: role-gate ใครเห็นราคาทุน, audit log, state 'ราคายังไม่อัปเดต-ห้ามเสนอ' กันหัวหน้าลืมกรอก (single point of failure)

F8 FuelOrder กำไร/ลิตร + quote win/loss + ราคาคู่แข่งทำทีหลัง (คลื่น 2 หลัง F7)

intelligence ที่ทำเงิน — ปรับ ZoneMargin ให้ชนะ. marginPerLiter/totalAmount/totalProfit เป็น GENERATED columns (DB คิด เชื่อถือได้). ⚠️ landmine migration 20260511000001 drop คอลัมน์เหล่านี้ ห้ามรัน ต้อง CI กัน. ความเสี่ยง: win-rate survivorship bias ถ้าไม่บังคับปิด quote ทุกใบ — เซลล์กรอกแต่ที่ชนะ. ควร optional + reminder ใบค้างผล

F9 เครดิต: วงเงิน+เอกสาร+เช็ค+รับชำระทำทีหลัง (เงินจริง+กฎหมาย ต้องทำหลัง order มีตัวตน)

must-have สำหรับขายส่งเครดิต กันหนี้สูญ. schema 4 ตารางครบ แต่ logic เชื่อมยังไม่มี = แค่ที่เก็บข้อมูล. 3 รูรั่ว: (1) Payment ไม่ผูก orderId → ทำ AR aging รายบิลไม่ได้ (2) creditUsed เป็น stored field ไม่ atomic → race เกินวงเงิน (3) เช็คเด้งไม่ดึงเครดิตคืนอัตโนมัติ. + ไม่มี slip dedup/ยืนยันยอดเข้าจริง = ช่องสลิปปลอม. ต้อง audit trail + backup

F10 จัดส่ง+GPS+route optimizationGPS=ทำทีหลัง / route optimization=over-scope (ตัดจาก MVP)

GPS ดูตำแหน่งรถ ROI ดี. แต่ route optimization = VRP/NP-hard ต้อง external solver + ไม่มี schema Route/Stop/distance-matrix เลย = greenfield. รถน้ำมันมักส่งเที่ยวเต็มคัน/จุดน้อย ประโยชน์ต่ำ. ⚠️ ปนกัน pickup(ลูกค้าแจ้งทะเบียนมารับ) vs delivery(เราส่ง) ไม่มี deliveryMode field. GPS strategy ยังไม่ตัดสิน (มือถือคนขับ vs DLT vendor pull) + vendor API ยังไม่ได้ docs/creds = blocker. Vercel Hobby cron วันละครั้ง poll GPS ไม่ได้

F11 ระบบบัญชีover-scope ที่สุด (อย่าทำเอง — export ให้โปรแกรมบัญชีเดิม)

ไม่มี schema accounting เลย (ไม่มี ledger/journal/invoice/VAT/เลขรันเอกสาร) = greenfield ขนาดเท่า FuelOS ทั้งระบบ. ทำเองแข่ง FlowAccount/PEAK/Express ที่เดือนละไม่กี่ร้อย + เสี่ยงผิดกฎภาษี. ทุก persona แนะนำ: MVP แค่ export order/payment เป็น CSV ให้บัญชีเดิม. ต้องถาม CEO ว่า 'บัญชี' หมายถึงอะไรกันแน่ — ดูตัวเลข vs ยื่นภาษีจริง ต่างกัน 5-10 เท่า

F12 Continuity/ส่งต่องานไม่ใช่ฟีเจอร์แยก (ผลพลอยได้จาก F2+F5)

แก้ pain แท้ 'เซลล์ลาออกพาลูกค้าไป'. เกิดเองถ้า F2(assignee)+F5(CRM)+F3 ทำดี — ~0.5-1 วันเพิ่ม reassign/ownership-transfer UI + audit. แต่ถ้า contactNote ยัง string ลอย/ลูกค้ายังผูก LINE ส่วนตัวเซลล์ → 'มาทำแทนทันที' เป็นแค่คำขวัญ. ต้องมี flow โอนเจ้าของกลุ่ม LINE + ถอนสิทธิ์คนเก่า

👥 Pain point รายบทบาท

บทบาทปัญหาวันนี้ระบบช่วยอะไร (+ผลข้างเคียง)
CEO/Ownerลูกค้าตกหล่นแต่มองไม่เห็น, วัดทีมไม่ได้ (ตัดสินด้วยความรู้สึก), เซลล์ลาออกพาลูกค้าหนี, ต้องเป็นคนวิ่งหา OA token + vendor GPS เอง = bottleneckจอเดียวเห็นลูกค้าตกหล่น/win-rate/margin/เครดิต + daily summary + KPI dashboard + ความรู้ลูกค้าอยู่ในระบบ. แต่เสี่ยงเชื่อ KPI ที่ยังไม่ clean (undercount ดีลปิดทางโทร) แล้วตัดสินใจผิด + ต้องดูแล 2 ระบบ (Pool+FuelOS) ข้อมูลไม่เชื่อม
หัวหน้าขาย (Area/Branch Manager)ไม่รู้ใครค้างตอบ/ตกหล่น, ไล่ถาม KPI ทีละคน, เซลล์ขายราคาคนละราคากรอกราคาเช้าครั้งเดียวคุมทั้งทีม (F7) + เห็นใครค้างตอบ real-time (F2) + วัด KPI/win-rate รายคน (F3/F8). แต่กลายเป็น single point of failure (ลืมกรอกราคา=ทั้งทีมขายผิด) + ต้องดูแล map userId ครบ + จัดการการเมือง KPI
เซลล์ (Staff)สลับ 30 กลุ่ม LINE ในมือถือ, โทรถามราคาเช้า, คิดราคาเอง, ลูกค้าตกหล่นจอเดียวเห็นทุกกลุ่ม + ราคาขายอัตโนมัติ + ออกใบราคาจากแชท. แต่ถูกจับเวลา KPI รายคน (กดดัน/อาจ game ระบบ) + ต้องผูก LINE id ส่วนตัว (กลัวถูกจับตา) + งานเพิ่ม (ผูก CRM/กรอกแพ้-ชนะ) + ถ้าออกใบเกิน 3 คลิกจะเลิกใช้ + ถ้า map ไม่ครบระบบนับว่าไม่ตอบทั้งที่ตอบแล้ว
การเงิน/เครดิตวงเงิน/เช็ค/เอกสารอยู่ Excel หลายไฟล์, ไม่รู้บิลไหนค้าง, เช็คเด้งไม่รู้ตัววงเงิน+เช็ค+เอกสาร+รับชำระรวมที่เดียว (F9) กันหนี้สูญ. แต่ถ้าไม่มีปุ่ม 'สลิป→Payment' = พิมพ์ซ้ำ 2 รอบ + creditUsed เพี้ยนถ้าไม่ atomic + ไม่มีบัญชีเต็มต้อง export ไปทำต่อข้างนอก + รับผิดชอบสลิปปลอมที่ระบบเชื่อ
ฝ่ายจัดส่ง (Dispatch)โทรถามคนขับว่ารถอยู่ไหน, จัดรถ-จุดส่งในหัว/Excelจัดรถ-คนขับ-จุดส่ง + เห็นตำแหน่งรถ real-time. แต่ไม่มี Trip/Stop model = ยังจัดมือเหมือนเดิม + ถ้า route optimization ห่วยจะไม่เชื่อระบบ + ติด vendor GPS ที่ยังไม่ได้ docs + สับสน pickup vs delivery เสี่ยงจัดรถซ้อน
คนขับ (Driver)โทรรายงานตำแหน่งบ่อย, ข้อโต้แย้ง 'ส่งแล้ว/ยังไม่ส่ง'GPS box ส่งเอง + ถ่ายรูป+พิกัดยืนยันส่ง. แต่ถ้าใช้มือถือ = กิน battery/เน็ตหลุดต่างจังหวัด + รู้สึกถูกติดตามตลอด (แรงงานสัมพันธ์) + LIFF iOS cookie-drop bug ทำ login พังบางเครื่อง + ไม่มีลำดับจุดส่งชัดต้องคิดเส้นทางเอง
ลูกค้า (LINE ไม่ login)ทักแล้วตกหล่น/ตอบช้า, ไม่รู้ราคาทันที, ไม่รู้รถถึงยังตอบเร็วขึ้น ไม่ตกหล่น + ได้ราคา/ใบเสนอราคาไว + เห็นรถกำลังมา. แต่บอทตอบผิด/ตอบทับในกลุ่ม (ลูกค้ารายใหญ่ B2B อยากคุยคน) + ราคาบอทผิดในกลุ่มที่อีกเจ้าเห็น = ดราม่า + ข้อมูลแชทถูกเก็บ/AI อ่าน (PDPA ยังไม่มีนโยบาย)
Admin/IT (คนตั้งระบบ)ไม่มี dev ดูแล, ตั้งค่าหลายอย่างเองระบบ standalone แยกชัดจาก Pool. แต่ onboarding หนัก: map LINE userId ทุกคน + เชิญ OA เข้าทุกกลุ่ม + ตั้ง token/webhook/GPS key/cron/R2/backup เองโดยไม่มี runbook + ทุก deploy เสี่ยง migration ไม่ apply → หน้าพังเงียบ

🕳️ ช่องว่างที่น่าจะขาด (สิ่งที่ยังไม่ได้คิด)

  1. พิสูจน์เทคนิคก่อนทุกอย่าง (PoC): ยังไม่มีใครทดสอบจริงว่า LINE OA ในกลุ่มได้รับ webhook ข้อความที่ member (พนักงาน+ลูกค้า) พิมพ์กันเองครบไหม — F2/F3 ทั้งหมดพึ่งสิ่งนี้ ต้อง PoC 1 กลุ่มจริง 1-2 วันก่อนลงทุนสร้างทั้งระบบ
  2. นิยาม MVP / definition of done: 12 ฟีเจอร์แต่ไม่ระบุ 'ส่งของรอบแรก' คืออะไร — ทีมแนะนำ MVP = F1+F2+F7 ship ใน ~2 สัปดาห์
  3. ตาราง map LINE userId พนักงาน → User + flow onboarding (พนักงานทักบอท/สแกนผูกบัญชี): hard dependency ของ F2/F3 แต่ไม่มีในโค้ด/แผน
  4. relation จาก InboxConversation → Contact/CustomerEntity (สะพาน Inbox↔CRM): ตอนนี้ contactPhone/assignedToId เป็น string/field ลอยไม่มี FK ทำให้ F5/F6/F12 ต่อไม่ติด
  5. นิยาม KPI ที่วัดได้จริง: แยก first-response vs resolved, นับ burst/นอกเวลาทำการ/บอท/สติกเกอร์อย่างไร — ต้องล็อกก่อนเก็บข้อมูล ไม่งั้นวัดผลคนผิด
  6. groupId + conversationType บน InboxConversation + เปลี่ยน unique key + refactor webhook ingest รับ source.type=group — รากของ F1
  7. นิยาม scope F11 บัญชี: VAT/ใบกำกับภาษี/งบ vs แค่สรุปยอด — กระทบ scope มหาศาล ต้องตอบก่อนนับว่าทำได้
  8. baseline ปัจจุบัน (response-time/ตกหล่น/win-rate วันนี้เท่าไหร่): ถ้าไม่เก็บก่อน พิสูจน์ ROI ไม่ได้ว่าระบบช่วยจริง
  9. baseline migration สะอาดสำหรับ DB เปล่า + CI/smoke-test กัน landmine 20260511000001 (drop คอลัมน์กำไร) ถูกรันโดยไม่ตั้งใจ
  10. แผน data migration/import ลูกค้าเดิม+วงเงินเครดิตเดิม (จาก Excel/Pool): standalone เริ่มศูนย์ ถ้าไม่ import วันแรกระบบว่างเปล่าใช้ไม่ได้
  11. ตัดสินใจ infra: Vercel Hobby cron วันละครั้ง ทำ GPS poll/ตรวจแชทตกหล่น near-real-time ไม่ได้ + after() ถูก kill ทำข้อความตกหล่นเงียบ → ต้องเลือก Pro/worker แยก/queue+retry ตั้งแต่วันแรก
  12. concurrency/atomicity + slip-verification: creditUsed race เกินวงเงิน + สลิปปลอม/ซ้ำ + price snapshot ตอนออกใบ — ต้องเป็น DB transaction ไม่ใช่ read-modify-write
  13. RLS จริง: ทั้งระบบพึ่ง where orgId เขียนมือ (lib/prisma.ts บอก auto-scope แต่ไม่มี $extends) ลืมจุดเดียว = leak ข้อมูลข้ามบริษัท
  14. โมเดล Trip/Route/Stop + distance matrix + deliveryMode(pickup vs delivery): F10 route optimization สร้างไม่ได้บน schema ปัจจุบัน
  15. PDPA/consent + audit trail การแก้เงิน/เครดิต/ราคา + backup/PITR ของ DB บัญชี: CEO ขอ 'ตรวจสอบได้' แต่ยังไม่มีนโยบาย
  16. secret management + cost guard: OA token/GPS key/AI key/R2 ต้อง encrypted + อยู่ใน env เท่านั้น + AI budget cap (secret leak เกิดซ้ำทุกโมดูล Pool)

❓ คำถามที่ทีมขอให้ CEO ตัดสิน

  1. [เทคนิค-ด่วนสุด] ยอมให้ทำ PoC 1 กลุ่ม LINE จริง 1-2 วันก่อนสร้างทั้งระบบไหม? เพื่อยืนยันว่า OA เห็นข้อความที่พนักงาน/ลูกค้าพิมพ์ในกลุ่มครบ — ถ้าเห็นไม่ครบ F2/F3 (ใครตอบ/KPI) ต้องเปลี่ยนวิธีทั้งหมด
  2. [scope-สำคัญสุด] ถ้าต้องเลือก ship เร็วใน ~2 สัปดาห์-1 เดือน ยอมเอา F1+F2+F7 (กล่องแชทกลุ่ม + ใครตอบ/ค้างตอบ + ราคาเช้า) เป็น MVP แล้วเลื่อน F4/F9/F10/F11 เป็นคลื่นถัดไปได้ไหม?
  3. [F11 บัญชี] 'บริหารบัญชี' หมายถึงแค่ดูยอดขาย-รับเงิน-กำไร/export ให้บัญชีเดิม หรือต้องออกใบกำกับภาษี VAT/งบการเงินจริง? (ถ้าเต็มรูปแนะนำต่อ FlowAccount/PEAK แทนเขียนเอง — ต่างกัน 5-10 เท่าของงาน)
  4. [F10 route] รถน้ำมันมีกี่คันจริง และส่งแบบ 1 จุด/เที่ยวเต็มคัน หรือหลายจุด/เที่ยว? ถ้า <10 คัน/จุดน้อย รับได้ไหมที่ MVP ทำแค่ 'ดูตำแหน่งรถ + จัดรถด้วยมือ' แล้วเลื่อน optimization ไปเฟสหลัง?
  5. [พนักงานตอบที่ไหน] เซลล์จะตอบลูกค้า 'ในเว็บ FuelOS' หรือ 'ใน LINE กลุ่มจากมือถือส่วนตัว' เหมือนเดิม? และยอมให้พนักงานทุกคนผูก LINE userId ครั้งเดียวตอน setup ไหม? (เงื่อนไขบังคับของ F2/F3 — ถ้าไม่ผูก KPI ใช้ไม่ได้)
  6. [KPI] วัดเวลาตอบเฉพาะในเวลาทำการหรือ 24 ชม.? และจะเอาไปผูกประเมิน/จ่ายคอมเลย หรือใช้ดูเฉยๆ 1-2 เดือนให้ข้อมูล clean ก่อน? (ผูกผลตอนข้อมูลยังเพี้ยน = ทีมต่อต้าน)
  7. [บอทในกลุ่ม] ให้บอท auto-reply ราคาในกลุ่มลูกค้าเลย หรือให้บอทแค่เสนอคำตอบให้เซลล์กดส่ง? (ราคาผิดในกลุ่มที่หลายเจ้าเห็น = เสียเงิน/เสียลูกค้าจริง)
  8. [เครดิต/สลิป] เมื่อลูกค้าสั่งเกินวงเงิน ระบบควรบล็อก/เตือนแล้วขายต่อได้/ส่งขออนุมัติหัวหน้า? และสลิปในแชทตัดเครดิตทันทีจากรูป หรือต้องรอการเงินยืนยันยอดเข้าบัญชีจริง?
  9. [standalone] ยืนยันแยกขาดจาก Pool จริงไหม? ลูกค้า/บัญชี/ผู้ใช้เริ่มกรอกใหม่หมด + ดูแล 2 ระบบ — เคยกลับคำเรื่อง standalone (ChairOps) มาแล้ว ยอมรับ trade-off นี้แน่นอน?
  10. [infra/งบ] ยอมจ่าย Vercel Pro (~$20/เดือน ปลดล็อก cron ถี่+after() นานขึ้น) ไหม? และนิยาม 'real-time ตำแหน่งรถ' = ทุกกี่นาที? (กำหนดว่า GPS/ตรวจแชทตกหล่นทำ near-real-time ได้จริงหรือต้อง batch)
  11. [role-gate ราคา] ใครเห็นราคาทุน(DepotPrice)/มาร์จิ้น/ราคาคู่แข่งได้บ้าง — เซลล์เห็นต้นทุนจริงหรือเห็นแค่ราคาขายสุดท้าย? (ข้อมูลลับสุดยอด)
  12. [data import] ลูกค้าเดิม+วงเงินเครดิตเดิมอยู่ที่ไหน (Excel/Pool) และต้อง import วันแรกไหม? ถ้าไม่ import ระบบว่างเปล่าใช้ไม่ได้
  13. [GPS] รถมีกล่อง GPS DLT ติดทุกคันแล้วไหม vendor เจ้าไหน มี Pull API + docs/test account หรือยัง? (blocker ของ F10 — อย่า commit timeline จนกว่าจะได้)
  14. [F8 win/loss] บังคับเซลล์ปิดสถานะใบเสนอราคาทุกใบ (ชนะ/แพ้+ราคาคู่แข่ง) ไหม? ถ้าไม่บังคับ win-rate จะเห็นแต่ที่ชนะ (ปลอม)

⚠️ ความเสี่ยงเรียงลำดับ

ระดับความเสี่ยง
P0LINE OA อาจมองไม่เห็นข้อความที่ member พิมพ์ในกลุ่มแบบครบ → วัด 'ใครตอบ/ตอบเร็วช้า/ตกหล่น' (F2/F3) ไม่ได้จริง = ทำลายเหตุผลหลักของโปรเจกต์. ยังไม่มีใครทดสอบ — ต้อง PoC ก่อนสัญญา
P0Inbox เดิมรับแค่ 1:1 (drop event ไม่มี userId, unique [channelId,externalUserId], ไม่มี groupId) → ประตูหน้า F1 ใช้ไม่ได้จนกว่าจะ rewrite ingest + เปลี่ยน data model ไม่ใช่ patch
P0Scope creep รุนแรง — 12 ฟีเจอร์ = 4 ผลิตภัณฑ์ในตัวเดียว (~13-20+ dev-day). ถ้าไม่ตัด F11 บัญชี + F10 route optimization ออกจาก MVP เสี่ยงไม่ได้ ship อะไรเลยใน 1-2 เดือน ขัดเป้า 'เร็วจริง'
P0ไม่มีตาราง map LINE userId พนักงาน + พนักงานตอบจาก LINE ส่วนตัว → ระบบนับ 'ไม่มีคนตอบ' ทั้งที่ตอบแล้ว → KPI โทษผิดคน ทีมเลิกเชื่อระบบ
P0migration landmine 20260511000001 drop คอลัมน์กำไร generated (marginPerLiter/totalProfit) — ถ้าหลุดรันตอน setup DB ใหม่ = กำไรทั้งระบบหาย ไม่มี CI กัน
P0Credit race condition: creditUsed/creditGroupUsed เป็น stored field update แบบ read-modify-write ไม่ atomic → 2 ออเดอร์พร้อมกันทำเครดิตเกินวงเงินจริง = หนี้สูญ
P0สลิปในแชทไม่มี dedup/ไม่ยืนยันยอดเข้าจริง → ลูกค้าส่งสลิปปลอม/ใบเดิมซ้ำหลายออเดอร์ การเงินยืนยันผิด ตัดยอดให้ทั้งที่เงินไม่เข้า
P1ตัดสินใจ standalone แยก DB จาก Pool = ข้อมูลเริ่มศูนย์ + ดูแล 2 ระบบ + CEO เคยกลับคำเรื่อง standalone (ChairOps) → เสี่ยงสร้างแล้วต้อง merge กลับ (rework)
P1KPI หลอกตัวเอง: ดีลปิดนอกแชท(โทร) undercount + เซลล์กด 'รับทราบ' หยุดนาฬิกา + นับ burst/นอกเวลา → CEO ตัดสินใจ/ประเมินคนบนข้อมูลปลอม
P1webhook after() บน Vercel Hobby ถูก kill ก่อนงานเสร็จ (rehost รูป+AI) → สลิป/ออเดอร์ตกหล่นเงียบ ไม่มี log/retry — ขัดเป้า 'ไม่ตกหล่น' โดยตรง
P1บอท AI ตอบราคาน้ำมันผิด/ราคาเก่าในกลุ่ม (ราคาเปลี่ยนทุกเช้า) → ขายต่ำกว่าทุน/เสียลูกค้า/ข้อพิพาทต่อหน้าทุกคนในกลุ่ม
P1ราคา stale: หัวหน้าลืมกรอกราคาเช้า + valid_until เป็น string ไม่มีวันที่ → ระบบใช้ราคาหมดอายุเงียบๆ ขายต่ำกว่าทุนทั้งวัน (single point of failure ที่ตัวหัวหน้า)
P1GPS real-time + route optimization ทำไม่ได้จริงบน Hobby cron + vendor API ยังไม่ได้ docs → ฟีเจอร์ที่ CEO ขายเป็นจุดเด่นกลายเป็น batch lag เป็นชั่วโมง = ผิดความคาดหวัง
P1ไม่มี RLS จริง (พึ่ง where orgId เขียนมือ ไม่มี $extends) → ลืมจุดเดียวหรือ query ใหม่ = leak ข้อมูลลูกค้า/ราคา/เครดิตข้ามบริษัท
P1Adoption ต่ำ — เซลล์ไม่ยอมเปลี่ยนจากตอบ LINE ส่วนตัว + ไม่กรอก CRM/แพ้-ชนะ (ถ้าออกใบเกิน 3 คลิก) → ข้อมูลว่างเปล่า KPI/CRM/continuity พังตาม
