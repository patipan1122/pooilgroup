## 3. 🗣️ Debate Highlights (สิ่งที่ทีมเถียงกันจริง)

1. **มี source field หรือไม่?** — Audit + BA/SA/QA/Devil รอบแรกเชื่อว่า "ไม่มี ต้อง migrate". **Integration agent อ่านโค้ดจริงแล้วแก้:** `LedgerExpense.source` (`line`/`web`/`email`) **มีอยู่แล้ว** stamped ทุก create path → แท็บแหล่งที่มา **ไม่ต้องแก้ฐานข้อมูล**. (ที่เห็น `source='manual'` คือ `LedgerBudget` คนละ model.)
2. **"สแกน vs เพิ่มเอง" แยกยังไง?** — Architect ยืนว่าแยกได้จาก `originalUrl/thumbUrl`; ทีมที่เหลือยืนว่า `source` แยกพอแล้ว (`line`=ถ่าย/สแกนจาก LINE, `web`=office อัป/กรอกเอง). **สรุป:** ใช้ `source` เป็นตัวแบ่ง ไม่ต้องเดาจากรูป.
3. **Confirm-gate เช็คฝั่ง client พอไหม?** — UX บางส่วนคิดว่า "แค่ disable ปุ่ม". **ACC/SA/QA/Programmer ยืนแข็ง:** ต้อง server-side เพราะ `bulkConfirm` รับแค่ ids ไม่มี patch → client check ข้ามได้ → ยืนยัน 50 ใบรวดโดยไม่มีสาขาได้. **สรุป:** บังคับใน server ทั้ง 3 path; client disable เป็นแค่ชั้น UX.
4. **#4 ลบ/อนุมัติ — เต็มหรือเบา?** — PM/BA/SA อยากได้ maker/checker เต็ม; Devil/Owner/User อยากตัดทิ้ง. **สรุป (sequenced):** ลบเอง <5 นาที ทำเลย (เจ็บจริง), คิวอนุมัติเต็มรอ CEO เคาะ.
5. **#5 settings — รื้อ web ด้วยไหม?** — UI/UX รอบแรกเสนอ re-skin web 8 cards. **Owner/Devil/PROG ยืนว่า LIFF console (5 แท็บ, deploy 5 มิ.ย.) แก้ปัญหา "ยาวบนมือถือ" ไป 70% แล้ว** → UI/UX **ถอนข้อเสนอ re-skin ในรอบ 2**. สรุป: เติมแค่ 2 รูที่ขาดจริง.
6. **กรอบเขียว = อะไร?** — ทั้ง 12 ที่นั่งเถียงโดยเดาว่าเป็น chip-rail แต่ UX flag ว่า "ไม่มีใครเห็น mockup จริง แถว list วันนี้ตรงนั้นว่างเปล่า" → ยกให้ CEO ตัดสิน (ได้คำตอบแล้ว = chip-rail).

## 5. 🔗 Integration Map — เชื่อมของเดิมไม่ให้พัง

**Reuse (ไม่มี component ใหม่):**
- `source` enum เดิม → source-tabs **ZERO migration**
- `CompletenessDot` + `CompletenessSummaryStrip` + `StatusBadge` + palette emerald/amber/rose/zinc → กรอบเขียว (D3) + สัญญาณ confirm-gate (D1) + filter ใบเก่า ที่ขาดสาขา
- `setParam()` URL filter pattern → filter-collapse เป็น presentation ล้วน
- `LedgerLineMember.pendingBranchId` maker/checker pattern + `AuditLog` (action `LEDGER_EXPENSE_*`) → delete flow (D2)
- `createdAt` + `createdBy` → คำนวณหน้าต่าง 5 นาที **ฝั่ง server** (ห้ามใช้เวลาเครื่อง client)
- 8 settings managers ที่ web + LIFF **share กันอยู่แล้ว** → D5 เป็น expose+edit เท่านั้น

**Additive only (มี migration เล็กเดียว):** `expenseConfirmability()` server primitive (single source of truth ของ D1+D3) · `updateCategory` action · **3 nullable cols** บน `LedgerExpense` (`delete_requested_by`, `delete_requested_at`, `delete_reason`) ถ้าทำคิวอนุมัติทีหลัง · line-item card-per-item (CSS) · read card group→branch · token ใหม่ 2 ตัวใน `recheck.ts`: `branch_missing`, `category_missing`.

**Memory guardrails (P0 ห้ามพลาด):**
- ⛔ ทุก query/mutation ใหม่ **กรอง `companyId`** ไม่ใช่ `orgId` อย่างเดียว — bug class นี้เคยหลุด prod มาแล้ว [[feedback-ledger-query-must-filter-companyid-2026-06-06]]
- ⛔ LIFF money-write **re-verify id_token ทุก action** (iOS webview ลบ cookie)
- ⛔ **ห้าม hard-delete ใบเสร็จ** — void เท่านั้น (audit trail) · ใบ confirmed/locked/ส่ง TRCloud แล้ว = void/ใบทดแทนเท่านั้น แม้ใน 5 นาที
- ⛔ Branch = **shared Pool entity** → ledger แตะได้แค่ binding LINE-group→branch + เตือน shared ห้าม rename ที่ desync ChairOps/ClawFleet
- ⛔ Confirm-gate เช็ค **presence ของ branch+category เท่านั้น** — ห้ามแตะ `inputVatClaimable` (ถูกกันออกจาก patchSchema ตั้งใจแล้ว, แตะ = เปิดช่องที่ปิดไป)
- ⛔ migration ของ delete flow → cherry-pick แยก + apply เอง ห้าม auto-commit จาก parallel session [[feedback-concurrent-session-autocommit-migration-trap]]

## 6. 🧩 Feature Spec (MoSCoW)

### MUST (Wave 1 — additive, merge-safe, /bigfeature ได้เลย)
- **M1 · Confirm-gate (P0 บั๊ก)** — server-side presence check branch+category ทั้ง 3 path + fold เป็น token `branch_missing`/`category_missing` ใน completeness → จุดเตือน + ปุ่ม disable + นับ skip ใน bulk · seed branch "สำนักงาน/ส่วนกลาง" ให้เลือก · **backfill view:** ใบเก่า `status IN (confirmed,locked) AND (branchId IS NULL OR categoryId IS NULL)` โผล่ผ่าน filter ให้บัญชีไล่แก้
- **M2 · Form reflow (#6)** — line-items มือถือ default-collapse accordion + card-per-item < 768px · คง h-11/text-base (กัน iOS zoom + tap ≥44px) · ทดสอบมือจริง 320/375/390
- **M3 · กรอบเขียว chip-rail (D3)** — meta-rail ใต้ vendor: VAT dot + TR badge + confirmedBy (reuse เดิม)

### SHOULD (Wave 2)
- **S1 · Source-tabs + ส่วนตัว (D4)** — 4 แท็บ `?tab=` บน web `/ledger/expenses` (count helper ใช้ WHERE เดียวกับ list กัน badge เพี้ยน) · **ไม่ลง `/liff/ledger/my`** (มันถูก scope ตัวเองอยู่แล้ว)
- **S2 · Filter-collapse (#1)** — มือถือ = ปุ่ม "ตัวกรอง (n)" → bottom-sheet (status/tr/category) · desktop = chip + popover แถวเดียว · cc (VAT 🟢🟡🔴) คงเด่นผ่าน `CompletenessSummaryStrip` เดิม
- **S3 · Self-delete 5 นาที (D2 ครึ่งแรก)** — เจ้าของ + draft + ยังไม่ push TRCloud + server(now−createdAt)<5min → void ได้ · ปุ่ม "ขอลบ" เด้ง LINE หาบัญชี
- **S4 · Settings 2 gaps (D5)** — read card group→branch + `updateCategory`

### COULD (เฟสถัดไป · CEO เคาะก่อน)
- **C1 · สมุดค่าใช้จ่ายรายประเภท / Category Ledger** ← **ฟีเจอร์ใหม่จาก CEO (ดู §7)** — "ปรึกษาก่อน"
- **C2 · คิวอนุมัติลบเต็ม (maker/checker)** — 3 cols + accountant approve/reject ในรายการ
- **C3 · comment / ตีกลับใบ** ในกรอบสถานะ

### WON'T (v1 — ขีดเส้นชัด)
สีใหม่ · dashboard สถานะแยกหน้า · รื้อ web settings 8 cards · หน้า inbox อนุมัติลบ · ตาราง delete-request (รอ C2) · per-action/member permission matrix · แท็บ source ที่ schema แบ็คไม่ได้ · เพิ่มค่า enum source.

## 7. ❓ ฟีเจอร์ใหม่ "ปรึกษาก่อน" — สมุดค่าใช้จ่ายรายประเภท (Category Ledger)

**CEO พูด (Q1):** "อยากวางโครงสร้างให้ดูบิลย้อนหลังของประเภทเดียวกันได้ — ค่าใช้จ่ายจ่ายประจำ เช่น ค่าไฟสาขานั้น ค่าน้ำสาขานั้น ค่าน้ำแข็ง — ดูย้อนหลังดูความเปลี่ยนแปลง คล้ายเล่มสมุดค่าใช้จ่าย ดูรายเดือน/รายปีได้เลย"

**ตีความ (2 ชั้น):**
- **7a · Category history/trend view (เบา · reuse data ล้วน)** — เลือกหมวด (+สาขา) → เห็นใบทั้งหมดของหมวดนั้น group ตามเดือน + ยอดรวม/เดือน + กราฟเส้นเล็ก ดูแนวโน้ม. ใช้ field เดิม (`categoryId`, `branchId`, `expenseDate`, `total`) · ไม่ต้อง schema ใหม่ · drill จาก category filter หรือ route ใหม่ `/ledger/categories/[id]`. **= "เล่มสมุดรายประเภท" ที่ CEO อยากได้โดยตรง.**
- **7b · บิลประจำ / recurring (หนักกว่า)** — mark หมวดเป็น "บิลประจำรายเดือน" + เตือนถ้าเดือนนี้ยังไม่มีบิล หรือยอดกระโดด >X% (แบบ Bainy "บิลประจำ"). ต้องเพิ่ม flag + logic cadence.

**✅ CEO LOCKED (2026-06-06):**
- **C1a · เข้าได้ 2 ทาง (both):** (1) drill จากชิปหมวดในหน้ารายการ → เด้งดูประวัติหมวดนั้น + (2) เมนูใหม่ **"สมุดค่าใช้จ่าย"** แยกหน้า
- **C1b · เลือกแกนได้ทั้งสอง:** ดู **ตามหมวด** (ค่าไฟทั้งบริษัท) หรือ **หมวด×สาขา** (ค่าไฟของสาขานั้น) — toggle ในหน้าเดียว
- **C1c · เฟสแรก = 7a เท่านั้น (ดูย้อนหลัง + กราฟ):** รายการบิลของหมวด group ตามเดือน + ยอดรวม/เดือน + **กราฟเส้นแนวโน้ม** (รายเดือน/รายปี). **เลื่อน 7b** (เตือนบิลประจำขาด/ยอดกระโดด) ไปเฟสถัดไป
- **Reuse:** field เดิมล้วน (`categoryId`, `branchId`, `expenseDate`, `total`) · ไม่ต้อง schema ใหม่ · ทุก query กรอง `companyId` · scope ตาม role เดิม (member เห็นเฉพาะสาขาตัวเอง). route ใหม่ `/ledger/categories/[id]` หรือ `/ledger/ledger-book`.
- **Build path:** C1 พร้อมเข้า `/bigfeature` ได้เลยหลัง Wave 1/2 (additive, reuse, ไม่มี migration) — ทีมแนะทำหลัง W1 (ปิดบั๊ก P0 ก่อน).

## 8. ⚠️ Risks (Top 5) + 🚫 Out of Scope

**Risks:**
1. **Legacy null rows** — ใบเก่าที่ยืนยันแล้วไม่มีสาขา/หมวด (บั๊กเดิม) — ต้อง backfill view ให้บัญชีไล่แก้ ไม่งั้น P&L รายสาขาเพี้ยน
2. **companyId leak** — query ใหม่ลืม companyId = รั่วข้ามนิติบุคคล (เคยหลุดมาแล้ว)
3. **bulkConfirm race** — ยืนยันหลายใบรวด ต้องเช็ค guard ต่อ row ฝั่ง DB (Architect blind-spot)
4. **iOS LIFF cookie drop** — money-write ต้อง re-verify id_token
5. **Parallel-session migration trap** — delete-flow migration ต้อง cherry-pick แยก + apply เอง

**Out of scope (v1):** ดู WON'T §6.
