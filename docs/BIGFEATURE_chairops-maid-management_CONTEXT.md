## Auth / Role System

- `lib/chairops/auth/session.ts` — `getSession()`, `requireAuth()`, `requireRole()`, `requireExactRole()`
- `lib/chairops/auth/role-guards.ts` — `canManageUser()`, `canAssignRole()`, rank: MAID=TECHNICIAN=1 < OFFICE=2 < MANAGER=3 < CEO=4 < ADMIN=5
- Inactive users (`isActive=false`) → `getSession()` returns null → 403 redirect
- Maids login via LINE LIFF → invite link → `signInvite(userId)` token → `/api/auth/line-login`

## Design Tokens
- ChairOps uses `.co-` prefix CSS tokens (e.g., `bg-[var(--co-surface)]`)
- Mobile-first · all /m/* pages render inside LINE LIFF MaidShell
- Admin pages: `.ch-scope` class on layout

## Consistency Requirements
- `requireRole(ADMIN)` → `canManageUser` BEFORE every user-management mutation
- `writeAudit(...)` inside every `$transaction` that mutates a user
- `revalidatePath` on `/chairops/users` after every mutation
- No bypass of RLS (`orgId` filter on every Prisma query)
- Migration required before adding new fields to ChairopsUser
