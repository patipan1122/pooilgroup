- 🔴 **ระดับความหวาน/ราคานมทางเลือก ที่แน่นอนของสาขา pilot** — ต้องเปิดแอปจริง capture

### โครงสร้างตัวเลือก (พันธุ์ไทย)
- **อุณหภูมิ (บังคับเลือก 1):** ร้อน / เย็น / ปั่น — บางเมนูมีเฉพาะบางแบบ · **ราคาต่างกันตามแบบ** (เย็น > ร้อน ~5-10฿ · ปั่นแพงสุด)
- **ความหวาน:** พบ "หวานปกติ / หวานน้อย" (ปกติ≈75%) — **จำนวนระดับเต็มยืนยันไม่ได้**
- **น้ำแข็ง:** ปกติ/น้อย ยืนยันได้ · แยก/ไม่ใส่ = มาตรฐานเดลิเวอรีทั่วไป (เฉพาะพันธุ์ไทยยืนยันไม่ได้)
- **ขนาดแก้ว:** 🔴 **น่าจะขนาดเดียว ไม่มี upsize** (ราคาเดียวต่อเมนู ไม่มีตารางแยกขนาด) ← ต่างจาก Amazon → **data model ต้องรองรับ size แบบ optional per-brand**
- **Topping/shot/นมพิเศษ:** ผ่านเมนู DIY (~150฿) · ราคา add-on แยกไม่พบ

- สะสม: **ทุก 20฿ = 1 แต้ม** (ที่ร้านกาแฟ) · แต้มอยู่ 3 ปี

## โครงสร้าง option/modifier มาตรฐาน (Grab/LINEMAN/foodpanda) ← นี่คือ schema ของเรา

### แม่แบบ option group (ทั้ง 3 แพลตฟอร์มบรรจบกัน)
| # | กลุ่ม | single/multi | บังคับ? | ตัวอย่างค่า | +ราคา |
|---|---|---|---|---|---|
| 1 | **ขนาด** | single | required | ปกติ / ใหญ่ (อัพไซส์) | +5 ถึง +15฿ |
| 2 | **ร้อน/เย็น/ปั่น** | single | required *(บ่อยครั้ง = คนละ SKU)* | ร้อน/เย็น/ปั่น | ปั่น +5-10฿ |
| 3 | **ความหวาน** | single | required | **หวานปกติ 100% / น้อย 50% / น้อยมาก 25% / ไม่หวาน 0%** | 0฿ |
| 4 | **น้ำแข็ง** (เฉพาะเมนูเย็น) | single | opt/req | ปกติ / น้อย / เยอะ / **แยกน้ำแข็ง** | ปกติ 0 · **แยก +10฿ (พันธุ์ไทย)** |
| 5 | **ท็อปปิ้ง** | **multi** | optional | ไข่มุกบุก +20 · น้ำตาลโตนด +20 · คาราเมล +15 · วิปครีม +10-15 · เจลลี่ | ต่อชิ้น |
| 6 | **เพิ่มช็อต** | single/stepper | optional | +1 / +2 ช็อต | +10-20฿/ช็อต |
| 7 | **เปลี่ยนนม** | single | optional | ปกติ / โอ๊ต / อัลมอนด์ / ถั่วเหลือง | +15-25฿ |
| 8 | **หมายเหตุถึงร้าน** | free text | optional | "ไม่ใส่หลอด" "กาแฟเข้ม" | 0฿ |

### หลักการ schema (สำคัญต่อ data model)
- โมเดลกลาง: **`option_group { min_select, max_select, required, choices[] }`** + **`choice { label, price_delta_cents }`**
  - `min=1,max=1` = required single (ขนาด/หวาน) · `min=0,max=N` = optional multi (ท็อปปิ้ง)
- **Conditional visibility จำเป็น**: เลือก "ร้อน" หรือ "ปั่น" → **ซ่อนกลุ่มน้ำแข็ง** (field `visible_if` ผูกกับ choice ของอีกกลุ่ม)
- ร้อน/เย็น: รองรับทั้ง 2 แบบ — (ก) option group + conditional-hide, หรือ (ข) แยกเป็นคนละ item (Amazon แยกจริง)
- ทำ **preset สำเร็จรูป** "ความหวาน 4 ระดับ" + "น้ำแข็ง 4 แบบ" (เลียนแบบ Wongnai template) → ร้านกดใช้เลย ไม่ต้องพิมพ์ใหม่ทุกเมนู
- Cart โชว์ option ใต้ชื่อเมนู + แก้กลับได้ + สรุปเงิน (อาหาร+ค่าส่ง+ส่วนต่างถ้าต่ำกว่าขั้นต่ำ) ก่อนยืนยันเสมอ

### ⚠️ เรื่องขนาดแก้ว (กระทบคำตอบ CEO ข้อ 9)
- **ทั้ง 2 แบรนด์ไม่ได้ทำ 16/22oz แบบ Starbucks** — พันธุ์ไทย = **ขนาดเดียว** · Amazon = **ปกติ + อัพไซส์ (ร้อน) +10฿**
- → "ขนาดแก้ว" จริง ๆ = ปุ่ม **ปกติ/ใหญ่** ไม่ใช่ S/M/L · แต่ data model ควรรองรับ size แบบ optional per-brand (เผื่อบางเมนู/สาขามี)
