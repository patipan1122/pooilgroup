## 0. 🧩 ปัญหาที่ CEO ตั้งต้น

เจพีซิ้งค์ กรุ๊ป จด VAT → ซื้อของมี VAT 7% **เอาภาษีซื้อ (input VAT) ไปหักภาษีขายได้** — แต่**ต่อเมื่อใบกำกับภาษีเต็มรูปถูกต้องสมบูรณ์** (มีชื่อ/ที่อยู่/เลขผู้เสียภาษีของเจพีซิ้งค์ในฐานะผู้ซื้อครบ). ทุกวันนี้ระบบ "แนบใบเสร็จ" ดึงแต่ฝั่ง**ผู้ขาย** ไม่เคยตรวจ**ผู้ซื้อ** และไม่รู้ว่าใบไหนขอคืน VAT ได้จริง → **ภาษีซื้อตกหล่น = เสียเงินฟรี + เสี่ยงโดนปรับถ้าเอาใบที่ขอคืนไม่ได้ไปขอคืน**

> CEO key insight (Q7): "ถ้ามี VAT มันควรขอคืนได้ทั้งหมด บางทีที่ขอไม่ได้เป็นเพราะคนออกผิด/กรอกชื่อผิด" → **หน้าที่ของฟีเจอร์ = จับใบที่ "ควรขอคืนได้แต่ติดปัญหาเพราะออกผิด" แล้วไล่แก้ให้กลับมาขอคืนได้ครบ**

## 1. 🎯 Goal & Success Metrics

- **เป้าหมายธุรกิจ:** กู้ภาษีซื้อที่เคยตกหล่นกลับคืน + ลดความเสี่ยงโดนสรรพากรปรับ โดยไม่เพิ่มภาระนักบัญชีเกินจำเป็น
- **Headline metric (Q7=a + CEO reframe):** "ยอดภาษีซื้อที่กู้คืนได้/เดือน" = ยอด VAT ก้อน**เขียว** (ขอคืนได้) ที่ระบบช่วยจับ — และยอดที่ยังติด**เหลือง/แดง** ที่กำลังไล่แก้ให้เป็นเขียว
- **Supporting metric:** จำนวนใบ เหลือง/แดง ที่ถูก "แนบใบใหม่ทดแทน" จนกลายเป็นเขียวสำเร็จ (remediation rate)
- **Definition of Done:** ทุกใบที่มี VAT มีสถานะสี (เขียว/เหลือง/แดง) + เหตุผล · กรองตามสีได้ · แนบใบทดแทนได้ · ยอดภาษีซื้อ "ขอคืนได้ / ขอคืนไม่ได้→ต้นทุน" แยกกันชัด

## 2. 👥 User Personas

- **นักบัญชี (1–3 คน)** — ผู้ตัดสินสุดท้าย: ยืนยันใบ, override คำเตือน, ไล่ตามใบเหลือง/แดงให้ร้านออกใบใหม่
- **พนักงานหน้างาน (~6 คน)** — ถ่ายรูปใบเสร็จส่งเข้า LINE (capture only)
- **CEO** — ดู dashboard/รายงาน: ยอดภาษีซื้อขอคืนได้ vs ติดปัญหา, ใบไหนยังต้องตาม

## 3. 🚶 User Journey

1. พนักงานถ่ายใบส่งเข้า LINE → AI อ่าน (เหมือนเดิม) → สร้าง draft
2. ระบบ **เติมผู้ซื้อจาก master (เจพีซิ้งค์)** + AI **หาเลขภาษี 0305564001581 บนใบ** + เครื่องตรวจ 7 องค์ประกอบ ม.86/4 → ให้**สถานะสี**
3. ในรายการ/รายงาน: แต่ละใบมี **วงกลมสีเล็ก** (เขียว/เหลือง/แดง) + **filter ตามสี** + **แถบสรุปสถานะ** (เขียว X / เหลือง Y / แดง Z + ยอด VAT ที่ยังติด)
4. นักบัญชีกด **"แก้ไข"** ใบเหลือง/แดง → เห็นชัดว่า**ผิดตรงไหน** (มี VAT แต่ใบย่อ / ผู้ซื้อไม่ตรง / ขาด element อะไร) → 2 ทางเลือก:
   - **a) แนบใบใหม่ทดแทน** (ใบกำกับเต็มรูปที่ขอจากร้าน) → **เก็บทั้ง 2 ใบ** → สถานะ flip เป็น**เขียว**
   - **b) override** (ถ้านักบัญชีตัดสินว่าใช้ได้) → เก็บ log
5. ยืนยัน → นับเข้า "ภาษีซื้อขอคืนได้" → push เข้า TRCloud (เป้าหมาย: realtime API)

**Screens ที่ต้องมี/แตะ:** รายการ expenses (เพิ่ม status dot + filter + summary bar) · หน้าแก้ไข expense (เพิ่ม panel "สถานะใบกำกับ + ผิดตรงไหน" + ปุ่มแนบใบทดแทน) · การ์ด LINE (เพิ่มบรรทัดสถานะสี — optional)

## 4. ✅ Feature List (MoSCoW)

### Must-have (v1)
- **M1 · ดึง+verify ผู้ซื้อ** — เติมจาก master, AI หาเลขภาษีบนใบ, ตัดสินด้วยเลข 13 หลัก **exact** (ผิด 1 หลัก = ไม่ผ่าน), ชื่อ/ที่อยู่เป็นสัญญาณ soft
- **M2 · whitelist เลขภาษีทั้งเครือ** — จับ "ใบออกผิดบริษัทในเครือ" (จ่ายโดยเจพีซิ้งค์ แต่ใบออกชื่อ POOIL ฯลฯ = ขอคืนไม่ได้)
- **M3 · เครื่องตรวจความสมบูรณ์ ม.86/4 (deterministic)** — เช็ค 7 องค์ประกอบ → ไล่เกรด เขียว/เหลือง/แดง (ไม่ใช้ AI ตัด, ต่อยอด `recheck.ts`, ผลคงที่ ตรวจย้อนได้)
- **M4 · สถานะสีในรายการ + หน้าแก้ไข** — วงกลมสีเล็ก + ข้อความ "ผิดตรงไหน"
- **M5 · filter ตามสี + แถบสรุปสถานะ** — กรองเหลือง/แดงเพื่อไล่ตาม + นับยอดแต่ละสถานะ
- **M6 · flow แนบใบทดแทน** — แนบใบใหม่เข้า expense เดิม, เก็บทั้ง 2 ใบ, สถานะ flip → เขียว, audit
- **M7 · แยกภาษีซื้อ 2 ก้อน** — "ขอคืนได้" (เข้า ภพ.30) vs "จ่ายแต่ขอคืนไม่ได้ → ลงต้นทุน" (ในข้อมูล + แสดงผ่าน filter/summary)
- **M8 · ใบกำกับอย่างย่อ (ม.86/6) = เหลือง** "ลงค่าใช้จ่ายได้ แต่ขอคืน VAT ไม่ได้"
- **M9 · override เฉพาะนักบัญชี/แอดมิน + audit log** (ใคร/เมื่อไหร่/เหตุผล)

### Should-have (v1 ถ้ามีเวลา)
- TRCloud **realtime API push** (ผู้ซื้อ + ภาษีซื้อแยกขอคืนได้/ไม่ได้) — *ขึ้นกับ field spec จริง + เลี่ยง shared company 31*
- เตือนสถานะสีบน**การ์ด LINE** ตอนถ่ายส่ง (early signal)

### Could-have (v2)
- flag ภาษีซื้อต้องห้ามอื่น (ค่ารับรอง, รถยนต์นั่ง ≤10 ที่นั่ง) — ต้องตีความเจตนา ให้คนตัดสินก่อน
- เตือน "ใกล้พ้นกำหนดยื่นภาษีซื้อ" (ใบเหลือง/แดงที่ค้างนาน)
- WHT (ภงด.3/53)

### Won't-have (out of scope v1 — explicit)
- **WHT** เฟสนี้ (Q3=a) · **auto-post** (คง never-auto-post) · **ใบรับรองแทนใบเสร็จเอาไปขอ VAT** (ผิดกฎหมาย — ใช้ได้แค่เป็นต้นทุน) · **ขยายทุกบริษัทในเครือเต็มรูป** (เริ่มเจพีซิ้งค์ก่อน) · **block แข็ง** (CEO เลือกเตือน+บันทึกไว้ก่อน ไม่บล็อก)

## 5. 🗄 Data Model (ส่วนเพิ่ม บน `LedgerExpense`)

| field | ชนิด | หมายเหตุ |
|---|---|---|
| `buyer_tax_id_snapshot` | text? | เลขภาษีผู้ซื้อ ณ เวลาบันทึก จาก **master** (ไม่ใช่ OCR) |
| `buyer_name_snapshot` | text? | ชื่อผู้ซื้อจาก master |
| `buyer_match_status` | enum | `matched` / `mismatch` / `not_found_on_doc` (ผล verify OCR-vs-master ด้วยเลข 13 หลัก) |
| `completeness_status` | enum | `green_full` / `yellow_partial` / `red_invalid` (เกรด ม.86/4) |
| `completeness_missing` | json? | element ที่ขาด เช่น `["buyer","vendor_tax_id","vat_line"]` (โชว์ "ผิดตรงไหน" + audit) |
| `input_vat_claimable` | bool? | ภาษีซื้อขอคืนได้ไหม (null=ยังไม่ตัดสิน) — **ใช้ยอด `vat` เดิม ไม่เก็บเลขซ้ำ** |
| `input_vat_block_reason` | enum? | `abbreviated_86_6` / `buyer_mismatch` / `wrong_entity` / `incomplete_invoice` / `entertainment` / `passenger_car` / `other` |
| `replaced_by_id` / `replacement_of_id` | fk? | เชื่อมใบเดิม ↔ ใบทดแทน (**เก็บทั้ง 2 ใบ + 2 รูป**) |
| `override_by` / `override_at` / `override_reason` | — | audit เมื่อนักบัญชี override |

> **กฎสี (deterministic):**
> 🟢 **เขียว** = ใบกำกับเต็มรูป + ผู้ซื้อ(เลขภาษี)ตรง + VAT แยกบรรทัด → **ขอคืนได้**
> 🟡 **เหลือง** = บันทึก/ลงค่าใช้จ่ายได้ แต่ขอคืน VAT ไม่ได้/ยังไม่ได้ — ใบอย่างย่อ ม.86/6, ขาด element รอง (ที่อยู่/สาขา), ชื่อ/รายละเอียดผิดเล็กน้อยจากคนออกผิด → **ต้องขอใบใหม่มาแนบ**
> 🔴 **แดง** = ขาดของบังคับ (เลขภาษีผู้ขายไม่ครบ / ไม่มี VAT แยก / **ผู้ซื้อเป็นบริษัทอื่นในเครือ/นอกเครือ**) → ขอคืนไม่ได้จนกว่าจะแก้

> Migration ต้อง **backfill ใบเก่าด้วย default ปลอดภัย** (claimable=null) · ไม่แตะใบที่ confirmed/locked แล้ว

## 6. 🔌 Integration Points

- **OCR:** ใช้ pipeline เดิม (gemini-3.1-flash-lite + budget-guard). **ไม่เพิ่ม cost** — buyer ไม่ได้ให้ AI อ่านชื่อ แค่ "หาเลขภาษีบนใบ"; ความสมบูรณ์คำนวณ deterministic ฟรี
- **Master ข้อมูลบริษัท:** `Company` (เจพีซิ้งค์ taxId `0305564001581`, ที่อยู่ 112 หมู่10 ต.จักราช อ.จักราช นครราชสีมา 30230) + ต้องเพิ่ม **whitelist เลขภาษีทุกบริษัทในเครือ**
- **TRCloud (Q4 = realtime API ที่ CEO อยากได้):** push ผ่าน api-connector2 create endpoint แทน CSV. ส่งผู้ซื้อ + แยกภาษีซื้อขอคืนได้/ไม่ได้
  - ⚠️ **depends:** field spec จริงของ TRCloud (มีช่อง "ภาษีซื้อขอคืนได้" แยกไหม) · เลี่ยง **shared company 31** ([[trcloud-shared-company-warning]]) · มี parallel session ทำ TRCloud AP-push อยู่ (migration `20260605180000` ยังไม่ apply) → ต้อง sync ไม่ให้ชนกัน

## 7. 🚨 Edge Cases & Error Handling

1. **VAT-inclusive (ไม่มีบรรทัด VAT แยก)** — ใบไทยส่วนใหญ่ → OCR ได้ VAT=0. **ห้ามเดา VAT=7%×ยอดเอง** (ม.86/4(7) ต้องแยกบรรทัด) → ถ้าไม่มีบรรทัดแยก = ไม่ใช่ใบเต็มรูป → เหลือง/แดง
2. **ชื่อผู้ซื้อพิมพ์ตก/ผิดจากคนออก** (เคสที่ CEO เน้น) — เลขภาษี 13 หลักตรง แต่ชื่อเพี้ยน → **เหลือง** "ผู้ขายกรอกชื่อผิด ขอใบแก้" (ไม่ใช่แดง เพราะเลขภาษียืนยันว่าเป็นเรา)
3. **เลขภาษีผิด 1 หลัก / ออกชื่อบริษัทอื่นในเครือ** — **แดง** (false-accept แพงสุด ห้ามปล่อย)
4. **OCR hallucinate ชื่อด้วย confidence สูง** (เคยเจอ "เจพีซิ้งค์"→"เจพีชิปปิ้ง" @0.95) → กันด้วยการตัดสินที่ **เลขภาษี exact** ไม่ใช่ชื่อ/confidence
5. **ใบกำกับอย่างย่อ** — สัญญาณ: ไม่มีเลขภาษี/ชื่อผู้ซื้อ, มีคำว่า "อย่างย่อ" → เหลือง M8
6. **แนบใบทดแทนแล้วยอดไม่ตรงใบเดิม** — เตือนนักบัญชีให้ตรวจ (อาจเป็นคนละรายการ)
7. **override รัว ๆ** — จำกัดเฉพาะนักบัญชี/แอดมิน + log ทุกครั้ง (กัน abuse)

## 8. ❓ Open Questions

1. **TRCloud realtime field spec** — มีช่อง "ภาษีซื้อขอคืนได้/ไม่ได้" + ผู้ซื้อ แยกไหม? (CEO ต้องเปิดหน้า API หรือถามทีม TRCloud) — gating Should-have S1
2. **Whitelist เลขภาษีทั้งเครือ** — ขอ list เลขผู้เสียภาษีของทุกบริษัทในเครือ (15 บริษัทใน TRCloud) — gating M2
3. **Baseline ความถี่** (Devil's Advocate) — นักบัญชีเจอใบมีปัญหา/ผู้ซื้อผิด เดือนละกี่ใบจริง? (ตั้งความคาดหวัง ROI; ไม่ block การ build)
4. **ที่อยู่/สาขาในใบกำกับ** — เจพีซิ้งค์มีหลายสาขา → "สำนักงานใหญ่/สาขาที่___" (ฉ.196/199) จะตรวจระดับไหน (เฟสแรกอาจเป็นเหลืองถ้าไม่ระบุ)

## 9. ⚠️ Risks (Top 5)

| Risk | โอกาส | Mitigation |
|---|---|---|
| **False-accept** (ใบเลขภาษีผิด/ผิดบริษัทเครือ หลุดเป็นเขียว) → ขอคืนผิด → เบี้ยปรับ 1 เท่า + เงินเพิ่ม 1.5%/ด. (ม.89/89-1) | กลาง | match เลขภาษี **exact**, ผิดบริษัทเครือ=แดง, ผู้ซื้อจาก master ไม่เชื่อ OCR |
| **False-reject** OCR เพี้ยน → เตือนผิดบ่อย → นักบัญชีเลิกเชื่อ | กลาง | ตัดสินด้วยเลขภาษีไม่ใช่ชื่อ; ชื่อเพี้ยน+เลขตรง=เหลืองไม่ใช่แดง |
| **ซ้ำซ้อนกับ TRCloud/นักบัญชี** (Devil's Advocate) | กลาง | LedgerLine = "คัดกรอง+ไล่แก้ก่อนคีย์" ไม่ใช่ตรวจซ้ำ; ยืนยัน baseline (Open Q3) |
| **Liability** — ระบบบอก "ขอคืนได้" แล้วสรรพากรไม่รับ | ต่ำ-กลาง | จุดยืน "ช่วยคัดกรอง/เตรียมเอกสาร" ไม่ใช่ "การันตี"; คนตัดสินสุดท้าย + ภพ.30 ที่ TRCloud |
| **Test set เล็ก (20 ใบ)** อาจไม่ครอบ edge case | กลาง | CEO เลือก 20 ใบ — **แนะนำแอบใส่ใบ "ออกผิดชื่อ" 2-3 ใบ** เช็คว่าจับได้ 100% ก่อนปล่อย |
