## 1. 🎯 Goal & Success Metrics

**เป้าหมายธุรกิจ:**
ให้ admin จัดการ lifecycle ของแม่บ้าน (เชิญ → onboard → ดูสาขา → เปลี่ยน → ไล่ออก) ได้ครบในหน้าเดียว โดยไม่เปลี่ยนหน้า · แม่บ้านทุกคน (รวม iPhone) เข้าระบบผ่าน LINE ได้เรียบร้อย

**Success metrics (วัดได้):**
1. แม่บ้านบน iPhone กดลิงก์เชิญ → เข้าหน้าบ้านสำเร็จ **ภายใน 3 tap ไม่มี error** ≥95%
2. Admin เชิญแม่บ้านใหม่ + ดูสาขาว่าง **ได้ในหน้าเดียวโดยไม่ navigate** ≥90% ของครั้ง
3. แม่บ้านที่ถูกไล่ออก **ถูก block LINE + data ยังอยู่** ภายใน 10 วินาทีหลัง deactivate
4. Admin ไม่สามารถ deactivate แม่บ้านที่ยังมียอดค้างฝาก → ระบบ block พร้อม warning

**Definition of Done:**
- iOS cookie drop แก้แล้ว · ทดสอบบน iPhone จริง 2+ เครื่อง
- หน้า Users มี vacancy badge ทุกสาขา + side panel invite/manage ทำงานได้
- Self-onboarding form (5 field) ปรากฏหลัง accept invite สำเร็จ
- Deactivate flow: settle gate + dropdown reason + LINE block + graceful screen

## 2. 👥 User Personas

**Persona A — Admin / CEO (ออฟฟิศ)**
- บทบาท: จัดการแม่บ้านทุกสาขา
- อุปกรณ์: คอมพิวเตอร์เป็นหลัก · บางครั้งมือถือ
- เป้าหมาย: เห็นภาพรวม 30 สาขา (ว่าง/มีแม่บ้าน) + จัดการได้เร็วไม่เปลี่ยนหน้า
- Pain point: ปัจจุบันหน้าเชิญไม่บอกว่าสาขาไหนมีแม่บ้านแล้ว → เชิญผิดสาขา · ต้องไป 2 หน้า

**Persona B — แม่บ้าน (MAID)**
- บทบาท: เก็บเงิน เช็คคลีน แจ้งซ่อม ที่สาขาประจำ
- อุปกรณ์: iPhone / Android · เปิดผ่าน LINE Rich Menu
- เป้าหมาย: เข้าใช้งานได้ทันทีหลังกดลิงก์ · รู้ว่าตัวเองอยู่สาขาไหน
- Pain point: iOS cookie drop → เข้าไม่ได้ · ไม่มีหน้ากรอก HR ข้อมูลตัวเอง

## 3. 🚶 User Journeys

### Journey A — Admin เชิญแม่บ้านใหม่

```
Admin เปิด /chairops/users
  → filter "แม่บ้าน" + เห็น vacancy badge (🔴 ว่าง / 🟢 มีแม่บ้าน) ทุกสาขา
  → คลิกสาขาว่าง หรือกดปุ่ม "เชิญ" ในแถวนั้น
  → Side panel เลื่อนออกมาทางขวา (ไม่เปลี่ยนหน้า)
  → กรอก: ชื่อแม่บ้าน + ยืนยันสาขา
  → กด "สร้างลิงก์เชิญ"
  → ได้ลิงก์ → copy/share ทาง LINE
  → (ถ้าสาขานั้นมี invite เก่าค้างอยู่ → auto-revoke เก่า แจ้งใน panel)
```

### Journey B — แม่บ้านรับลิงก์เชิญ (iOS)

```
แม่บ้านกดลิงก์ใน LINE
  → เปิด Safari (ไม่ใช่ LIFF webview ← iOS fix)
  → LINE Login → callback → session cookie ติด
  → หน้า Self-Onboarding Form (บังคับกรอกครั้งแรกก่อนใช้งาน):
      ชื่อ* | เบอร์มือถือ* | ผู้ติดต่อฉุกเฉิน* | เบอร์ฉุกเฉิน* | ที่ทำงานประจำ*
  → กด "บันทึกและเริ่มใช้งาน" → เข้าหน้าบ้านแม่บ้าน /chairops/m
```

### Journey C — Admin ไล่แม่บ้านออก

```
Admin เปิด /chairops/users → filter แม่บ้าน
  → คลิกแถวแม่บ้านที่ต้องการ → Side panel เปิด
  → เห็น: ยอดค้างฝากปัจจุบัน
  → ถ้ายอดค้าง > 0 → ปุ่ม "ไล่ออก" disabled + warning "ยังมียอดค้าง X บาท · ต้องฝากก่อน"
  → ถ้ายอดค้าง = 0 → ปุ่ม "ไล่ออก" active
  → คลิก "ไล่ออก" → Modal confirm:
      - Dropdown เหตุผล: ลาออกเอง / เลิกจ้าง / ย้ายสาขา / อื่นๆ
      - Note อิสระ (optional)
      - ยืนยันชื่อแม่บ้าน (safety)
  → confirm → deactivate + block LINE OA + บันทึก audit log
  → สาขานั้น badge เปลี่ยนเป็น 🔴 ว่าง ทันที
```

### Journey D — แม่บ้านถูกไล่ออกเปิด app

```
แม่บ้านกด LINE Rich Menu
  → ระบบ detect isActive=false
  → หน้า "ขอบคุณที่ร่วมงาน" (graceful screen):
      - ชื่อแม่บ้าน
      - "ขอบคุณที่ดูแลสาขา [ชื่อสาขา] มาอย่างดี"
      - เบอร์โทรออฟฟิศ (ถ้ามีข้อสงสัย)
      - ไม่มีปุ่มอื่น
```

### Journey E — Admin เปลี่ยนแม่บ้าน (ออกตัวเก่า + เชิญตัวใหม่)

```
Admin ทำ Journey C (ไล่ออก) กับแม่บ้านเก่า
  → สาขา badge เป็น 🔴 ว่าง
  → Admin คลิกสาขานั้น → Side panel "สาขาว่าง"
  → ทำ Journey A (เชิญ) ได้ทันที
  [optional] Cover ชั่วคราว:
  → แม่บ้านสาขาอื่น admin กด "Assign ชั่วคราว" ในขณะรอคนใหม่
```

## 4. ✅ Feature List (MoSCoW)

### Must-have (v1 · ไม่มีไม่ได้)

| # | Feature | หมายเหตุ |
|---|---|---|
| F1 | **แก้ iOS LIFF cookie drop** | workaround: `?openExternalBrowser=1` → Safari ไม่ใช่ webview OR URL fragment token | 
| F2 | **/chairops/users vacancy upgrade** | แต่ละแถวแม่บ้านแสดง "ว่าง / มีแม่บ้าน" badge · filter ดู "สาขาว่าง" ได้ |
| F3 | **Inline side panel** | invite/manage ไม่ navigate ออกจากหน้า users · slide-in panel ทางขวา |
| F4 | **Self-onboarding form** | 5 field บังคับ (ชื่อ เบอร์ ผู้ติดต่อฉุกเฉิน เบอร์ฉุกเฉิน งานประจำ) · ปรากฏ 1 ครั้งหลัง accept invite |
| F5 | **Auto-revoke old invite** | สร้าง invite ใหม่สาขาเดิม → revoke เก่าอัตโนมัติ + log audit |
| F6 | **Settle gate before deactivate** | ถ้ายังมียอดค้างฝาก → block deactivate + แสดงยอด |
| F7 | **Deactivation reason** | dropdown (4 ตัวเลือก) + optional note · บันทึกใน ChairopsAuditLog |
| F8 | **LINE OA block on deactivate** | เรียก LINE Messaging API blockMember ตอน deactivate · ไม่ลบข้อมูล |
| F9 | **Graceful deactivated screen** | isActive=false → หน้า "ขอบคุณที่ร่วมงาน" แทน error |

### Should-have (v1 ถ้ามีเวลา)

| # | Feature |
|---|---|
| S1 | Cover ชั่วคราว — admin assign secondary branch ให้แม่บ้าน (สูงสุด 1 สาขาเพิ่ม) |
| S2 | "Share ทาง LINE" จากหน้า invite โดยตรง (LINE Share API) แทน copy-paste |

### Could-have (v2)

- Multi-branch permanent assignment (junction table)
- แม่บ้านเห็นประวัติการทำงาน / เอกสารสัญญา ใน profile

### Won't-have (explicit)

- Full HR approval workflow (manager sign-off ก่อน deactivate) — ซับซ้อนเกินไปสำหรับ SME
- แม่บ้าน reset PIN / รหัสเอง (ใช้ LINE login ไม่มี password)
- Export payroll อัตโนมัติ (ยังไม่มีระบบ payroll)

## 6. 🔌 Integration Points

| Integration | ทำอะไร | Failure mode |
|---|---|---|
| **LINE Messaging API** — `blockMember` | ตอน deactivate → block LINE User ID ออกจาก OA | ถ้า API ล้ม → log error · deactivate ยังเดินหน้า · retry queue |
| **LINE LIFF** iOS fix | เพิ่ม `?openExternalBrowser=1` ใน invite link หรือใช้ URL fragment token | ถ้า user ไม่เปิด Safari → แสดง instruction "กด ⋯ → เปิดใน Safari" |
| **Supabase auth** | magic-link session ยังเหมือนเดิม | ไม่มีการเปลี่ยน auth provider |
| **ChairopsAuditLog** | บันทึกทุก action: invite/revoke/deactivate/line-block/onboarding | write audit ใน same transaction กับ main action |

## 7. 🚨 Edge Cases & Error Handling

| Case | การจัดการ |
|---|---|
| Admin deactivate แม่บ้านที่ยังมียอดค้างฝาก | Block deactivate + warning card "มียอดค้าง X บาท (N รอบ) · ต้องฝากก่อน" · link ไป /chairops/deposits |
| สร้าง invite ใหม่ สาขาที่มี invite เก่ายังไม่หมดอายุ | Auto-revoke เก่า + toast "ยกเลิกลิงก์เก่าแล้ว" · บันทึก audit `invite.revoked` |
| แม่บ้านใหม่ใช้ LINE account เดียวกับคนเก่า (rare) | ตรวจ lineUserId uniqueness ก่อน link · ถ้าชน → admin panel แจ้ง "LINE นี้ผูกกับบัญชีอื่นอยู่" |
| LINE blockMember API ล้ม | Deactivate ยังเดินหน้า · log `line.block_failed` · แสดง warning ใน user detail "LINE ยังไม่ถูก block · ติดต่อ admin ดำเนินการเอง" |
| Admin กด deactivate แล้วแม่บ้านกำลัง submit collect อยู่ | Transaction ด้าน collect เสร็จก่อน (isActive ตรวจที่ session ไม่ใช่ mid-request) · deactivate มีผลรอบ session ถัดไป |
| แม่บ้านกลับมากด invite link ที่หมดอายุ / ถูก revoke | หน้า error "ลิงก์นี้หมดอายุหรือถูกยกเลิก · ติดต่อออฟฟิศ" พร้อมเบอร์โทร |
| แม่บ้าน skip self-onboarding form | ไม่ได้ · form บังคับทุก field · `onboardingComplete = false` → redirect กลับ form ทุกครั้งจนกว่าจะกรอก |
| Admin ปิดบัญชีตัวเอง | Role-rank guard block (canManageUser = false สำหรับ self) — เหมือนเดิม |

## 9. ⚠️ Risks (Top 5)

| Risk | โอกาส | Mitigation |
|---|---|---|
| iOS fix ด้วย `?openExternalBrowser=1` — ใช้ได้กับ LINE Rich Menu URL ไม่ใช่ LIFF URL เสมอไป | กลาง | ทดสอบบน iPhone จริง 2 เครื่องก่อน deploy · มี fallback instruction "กด ⋯ เปิดใน Safari" |
| LINE blockMember API ต้องใช้ channel access token ที่มี permission พิเศษ — อาจยังไม่ได้ setup | สูง | ตรวจ LINE Developer Console ก่อนเริ่ม F8 · ถ้าไม่มีให้ CEO ขอ permission ก่อน |
| Self-onboarding form เพิ่ม friction ตอน first-use → แม่บ้านบางคนหยุดกลางทาง | กลาง | Form ออกแบบ 1 หน้า ไม่มี navigation · ทุก field ใน viewport เดียว · ภาษาไทย 100% |
| Settle gate อาจ block admin ถ้าแม่บ้านมียอดค้างมาก (admin ต้องไปจัดการยอดก่อน) | กลาง | แสดง link ตรงไปหน้า /chairops/deposits ของสาขานั้น · อย่าให้ admin ต้องหาเอง |
| Race condition: deactivate กับ collect submission พร้อมกัน | ต่ำ | isActive ตรวจที่ session cookie (per-request) ไม่ใช่ per-query — Supabase session middleware จัดการ |
