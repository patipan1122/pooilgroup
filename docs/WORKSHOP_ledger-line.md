## 1. 🎯 Goal & Success Metrics
**เป้าหมายธุรกิจ:** ทำให้ฝั่ง LINE ของ LedgerLine "ใช้งานได้จริง" สำหรับพนักงานหน้างาน — เก็บค่าใช้จ่ายเข้าระบบครบ ไม่ตกหล่น แล้วบัญชีตรวจ/ยืนยันเข้า TRCloud (book of record)

**Success metrics (30 วันหลังใช้จริง):**
- Capture coverage: รายจ่ายหน้างานเข้าระบบผ่าน LINE ≥70%
- Adoption: พนักงาน ≥5/6 คน บันทึกผ่าน LINE ≥3 ครั้ง/สัปดาห์
- บัญชี confirm draft ได้ภายในวันเดียวกัน (draft ไม่ค้าง)
- ต้นทุน AI ≤ ~2,000 บาท/เดือน (text ฟรี, รูป/`จด`+AI คิดงบ)

**Definition of Done:** พนักงานหน้างานคนใหม่ถ่าย/พิมพ์รายจ่ายใบแรกสำเร็จเองได้ใน LINE โดยไม่ต้องให้ใครสอน + การ์ดยืนยันสวย + บัญชีเห็น draft auto-tag สาขาถูกต้องในเว็บ

## 2. 👥 User Personas & Roles
- **พนักงานหน้างาน (~6):** บนมือถือ ใน LINE ทั้งวัน · งานเดียว = ส่งรูป/พิมพ์รายจ่าย · low-tech · ไม่ดูงบ
- **บัญชี (2-3):** ยืนยัน/แก้/จัดหมวด/export บน **เว็บ** · รับสรุป/แจ้งเตือนใน LINE 1:1
- **CEO:** ดู dashboard + รับสรุปวันละครั้งใน LINE 1:1
- **แอดมิน:** ตั้งค่ากลุ่ม, อนุมัติเปลี่ยนสาขา, เชิญสมาชิก

**Scope ต่อสมาชิก (จากลิงก์เชิญ):** ระบุ "ดูแลสาขาไหน / หมวดไหน" = **ค่าเริ่มต้น + เห็นสรุปของสาขา/หมวดนั้น** (ยืดหยุ่น ยังเห็นภาพรวมได้ · ไม่ใช่กำแพงตัด) — RLS ระดับ org เหมือนเดิม

## 3. 🚶 User Journeys

### A. กลุ่มสาขา (group = branch)
1. แอดมินดึง bot เข้ากลุ่ม LINE ของสาขา → พิมพ์ `/setting` → ผูก "กลุ่มนี้ = สาขา X"
2. พนักงานส่งรูปใบเสร็จในกลุ่ม → ระบบ **auto-tag สาขา X** → OCR → การ์ด "จดสำเร็จ ✅" (ตอบย่อในกลุ่ม + tag ชื่อคนส่ง, การ์ดเต็มไป 1:1 ของคนส่ง)
3. พิมพ์ `จด กาแฟ 45` → AI อ่าน → การ์ดยืนยัน/แก้ไข
4. บัญชียืนยัน/แก้บนเว็บ → export เข้า TRCloud

### B. กลุ่มกลาง (central group)
- ใบเสร็จเข้ามา → การ์ดมี **ปุ่มเลือกสาขา** ให้กดเลย (tag ทันที) + **กดดู/แก้ไขข้างใน** ได้ (เปิด LIFF แก้ทุกช่อง รวมวันที่/เวลา) · แก้ทีหลังได้เสมอ

### C. แชต 1:1 (ผู้ช่วยส่วนตัว)
- คุยกับ bot ตรงๆ → เก็บค่าใช้จ่ายของคนนั้น → ลงสาขา/หมวด **ตาม scope ที่ถูกเชิญ** (default)

### D. Onboarding (มีทุกทาง)
1. **ลิงก์เชิญแบบมีขอบเขต** → กดในมือถือ → LINE Login → เข้าระบบ + ผูก scope (สาขา/หมวดที่ดูแล) → ถ่ายใบแรกได้เลย
2. **แอดมินผูกให้ทีละคน** (map LINE userId ↔ Pool account) — 6 คนครั้งเดียวจบ
3. **ดึง bot เข้ากลุ่มที่มีอยู่ + `/setting`** ผูกสาขา

## 4. ✅ Feature List (MoSCoW · แผนเต็ม)

### Must (แกนหลัก)
- **M1. การ์ด Flex "จดสำเร็จ ✅"** — wire `LineConfirmCard` ที่สร้างไว้แล้ว เข้า webhook reply (เลิกตอบ plain text) · ฟิลด์: ยอด/ร้าน/วันที่/หมวด/สาขา/วิธีจ่าย + ปุ่ม **ยืนยัน · ✏️แก้ไข**
- **M2. แก้ไขแบบทั้งคู่** — ปุ่มเร็วในแชต (เลือกหมวด/สาขา postback) **+** ลิงก์ **LIFF** แก้ละเอียด (ยอด/ร้าน/วันเวลา) ไม่ต้องล็อกอินใหม่
- **M3. พิมพ์ → รายจ่าย** — ข้อความขึ้นต้น **"จด"** เท่านั้นถึงเรียก AI parse (เช่น `จด กาแฟ 45`) · ไม่มี "จด" = ไม่บันทึก (ไปทาง Q&A/เงียบ) → คุม token + ตัด noise ในกลุ่ม
- **M4. ดักซ้ำก่อนบันทึก (cheap)** — เทียบ **ยอดเงินซ้ำ** ในช่วง **วันนี้ + เมื่อวาน** เท่านั้น (ไม่สแกนทั้งประวัติ, ไม่ใช้ AI) → ถ้าซ้ำถามก่อน "เคยส่งแล้ว ส่งซ้ำไหม?"
- **M5. กลุ่ม = สาขา (auto-tag)** + **กลุ่มกลาง** (ปุ่มเลือกสาขาบนการ์ด, แก้ได้) + **`/setting`** ผูกกลุ่ม↔สาขา
- **M6. Security gate (P0)** — รับรูป/`จด`/Q&A เฉพาะ "กลุ่มที่ลงทะเบียน" + "สมาชิกที่ผูกตัวตน" · ตัวเลขเงินตอบเฉพาะกลุ่ม/DM ของ member (กันรูปขยะ + กันยอดเงินรั่วให้คนนอก + กันเผางบ AI)
- **M7. ระบบลิงก์เชิญแบบมีขอบเขต** — เชิญ + ระบุสาขา/หมวดที่ดูแล → LINE Login → join + ผูก scope
- **M8. Rich Menu (พนักงาน-centric)** — 📷ถ่ายใบเสร็จ · ⌨️พิมพ์รายจ่าย · 📋รายการของฉันวันนี้ · 🏢เปลี่ยนสาขา · 📖วิธีใช้ · 🆘แจ้งปัญหา · **"เปลี่ยนสาขา" ต้องขอแอดมินอนุมัติ**
- **M9. มาสคอต "JP"** — ใช้เป็น avatar การ์ด + ภาพ Rich Menu + การ์ดต้อนรับ + ภาพตอบในแชต (รายละเอียด §6.4)

### Should
- **S1. /setting เต็ม** (admin/บัญชี): ผูกสาขา · ตั้งหมวด/วิธีจ่ายเริ่มต้นของกลุ่ม · ดูฟังก์ชันที่ใช้ได้
- **S2. ตั้งวิธีจ่ายเริ่มต้น** (default payment) — ลดการกรอกซ้ำ
- **S3. คำสั่งช่วยเหลือ** `/help` `/menu` `/guide` `/members` + ภาษาธรรมชาติ
- **S4. รายการของฉันวันนี้** (LIFF list) — ดูใบที่ส่ง + สถานะ (ร่าง/ยืนยันแล้ว)
- **S5. สรุป/แจ้งเตือนงบ** — เด้งเฉพาะ CEO/บัญชี ใน 1:1 + สรุปวันละครั้ง (ไม่กวนกลุ่มสาขา)

### Could
- **C1. auto-เดาหมวด** (AI guess จาก OCR) + เรียนรู้คำที่เคยใช้ → set default ครั้งหน้า
- **C2. health-check ปุ่ม "ตรวจการเชื่อมต่อ LINE"** ใน /ledger/settings
- **C3. สติกเกอร์ LINE จริง** (LINE Creators Market — ดู §6.4 + Open Q)

### Won't (v1)
- /org สลับหลายบริษัท (ตอนนี้ 1 บริษัท), ปุ่ม "อัปเกรด"/billing (internal tool), แก้/ลบในแชต (ทำบนเว็บ/LIFF เท่านั้น), แจ้งเตือนงบเข้ากลุ่มสาขา

## 5. 🗄 Data Model (ส่วนเพิ่ม)
ใช้ตาราง `ledger_*` เดิม · เพิ่ม:
- `ledger_line_channel` + cols: `branch_id` (กลุ่มนี้=สาขาไหน, null=กลุ่มกลาง), `default_payment_method`, `default_category_id`, `rich_menu_id`, `kind` (branch | central | dm)
- **ตารางใหม่ `ledger_line_member`**: `channelId`/`orgId` · `lineUserId` · `poolUserId?` · `scopeBranchIds[]` · `scopeCategoryIds[]` · `role` (staff/admin/accountant) · `defaultPaymentMethod?` — เก็บ scope จากลิงก์เชิญ + per-user default
- **ตารางใหม่ `ledger_line_invite`**: `token` · `orgId` · `scopeBranchIds[]`/`scopeCategoryIds[]` · `role` · `expiresAt` · `usedBy?`
- `ledger_expense` ใช้ field เดิม: `branchId`, `categoryId`, `source` (line), `needsReview`, `createdById`; เพิ่ม `branchTagPending` (กลุ่มกลางยังไม่ระบุสาขา)
- **identity:** map `event.source.userId` → `User.lineUserId` (มี field unique อยู่แล้ว) สำหรับ attribution เท่านั้น
- ⚠️ ทุก migration ทำแบบ **surgical SQL** (มี schema drift — `[[pool-schema-drift-2026-05-21]]`)

## 6. 🔌 Integration & Mechanics

### 6.1 Webhook routing order
`/` command (gate role+source) → ข้อความขึ้นต้น **"จด"** → text→expense (AI ผ่าน budget-guard) → ไม่ใช่ → Q&A keyword (ฟรี) → ไม่เข้าเกณฑ์ → เงียบ. ทุกอย่าง gate ที่กลุ่ม/สมาชิกที่ลงทะเบียน

### 6.2 Reply vs Push
- Reply-only ทุกที่ที่ทำได้ (ใช้ replyToken ของ event) · OCR ใน after() ช้า → ถ้า token หมดอายุ fallback **Push** ไป groupId/userId
- Push เฉพาะ: การ์ดหลัง OCR เสร็จ (ถ้า reply ไม่ทัน), สรุปวันละครั้ง, budget alert (throttle 1/หมวด/รอบ) — ระวัง push quota

### 6.3 Identity & confirm (GOLDEN RULE)
- postback "ยืนยัน" บนการ์ด = **acknowledge เท่านั้น ไม่ flip status** → การยืนยันจริง (status=confirmed) เกิดบน **เว็บ** ผ่าน server action เดิม (accountant-only) — กันยืนยันมั่วในกลุ่ม + never-auto-post
- ปุ่ม "เปลี่ยนสาขา" = สร้างคำขอ → แอดมินอนุมัติ (ไม่ self-serve)

### 6.4 มาสคอต "JP" + สติกเกอร์ (workstream)
- **มี 5 รูปใน Google Drive** โฟลเดอร์ "Mascot jp" (IMG_0341–0345.PNG, owner patipan@jpsyncgroup.com)
- **ใช้ได้เลยในแอป (ผมทำให้):** ตัดพื้นใส (transparent PNG) + resize → avatar การ์ด Flex · ภาพ Rich Menu · การ์ดต้อนรับ · ภาพตอบ "จดสำเร็จ"/"รูปไม่ชัด" แทนข้อความเปล่า (เหมือนแนวมาสคอตแมวน้ำ ChairOps `[[jpsync-mascot-and-logo-2026-06-02]]`)
- **สติกเกอร์ LINE จริง (sticker keyboard):** ต้องส่งเข้า **LINE Creators Market** ด้วยบัญชี LINE ของ CEO + รอรีวิว (ผมทำเองแทนไม่ได้) — ผม **เตรียมไฟล์ให้ครบตามสเปก** (PNG โปร่ง ≤370×320, ชุด 8/16/24/40) แล้ว CEO อัปโหลด/submit
- **ทางลัด (แนะนำ v1):** bot ส่ง "ภาพมาสคอต" เป็น image/Flex message ได้เลย — รู้สึกเหมือนสติกเกอร์โดยไม่ต้องรอรีวิว

## 7. 🚨 Edge Cases & Error Handling
1. รูปเบลอ/มืด → "รูปไม่ชัด ถ่ายใหม่ให้เห็นยอดรวมชัดๆ 📷" (มาสคอต)
2. ส่งรูป/`จด` ซ้ำ (ยอดเดียวกัน วันนี้/เมื่อวาน) → "เคยส่งแล้วเมื่อ X · ส่งซ้ำไหม? [ใช่][ไม่]"
3. `จด` แต่ไม่มียอดเงิน → การ์ดช่องว่าง + ปุ่มเติม / "ใส่จำนวนเงินด้วยนะ เช่น จด กาแฟ 45"
4. ข้อความไม่ขึ้น "จด" และไม่ใช่คำถาม → เงียบ (ไม่จดมั่ว)
5. คนนอก/ไม่ใช่สมาชิก ส่งรูปในกลุ่ม → ไม่ประมวลผล (gate) + ไม่ตอบยอดเงิน
6. กลุ่มกลางไม่ระบุสาขา → draft `branchTagPending=true` ให้บัญชีเห็นชัด
7. OCR ช้า/replyToken หมดอายุ → fallback push (ไม่เงียบ)
8. เน็ตหลุดระหว่างอัปโหลด → "ส่งใหม่อีกครั้งนะ"
9. budget-guard เต็ม → เก็บรูปไว้ ไม่ OCR + แจ้ง
10. เปลี่ยนสาขาไม่ผ่านอนุมัติ → คงสาขาเดิม + แจ้งสถานะรออนุมัติ

## 9. ⚠️ Risks (Top 5)
1. **Bad-draft tax** — text/AI อ่านผิด สร้าง draft ขยะให้บัญชีล้าง → **กัน:** การ์ดยืนยันก่อนเสมอ + needsReview + ดักซ้ำ
2. **'free' ไม่ฟรีจริง** — ถ้าไม่ล็อก trigger "จด" จะเรียก AI ทุกข้อความ → **กัน:** "จด" เท่านั้นถึงเรียก AI; ดักซ้ำแบบ amount-match ไม่ใช้ AI
3. **Security/leak** — รูป/Q&A ungated = คนนอกสร้าง draft/เห็นยอด → **กัน:** M6 gate กลุ่ม+สมาชิก (P0)
4. **iOS LIFF cookie-drop** (`[[liff-magic-link-ios-webview-cookie-drop-2026-05-30]]`) — ปุ่มแก้ไขเด้งเว็บแล้วติด login → **กัน:** ใช้ LIFF auth ไม่ใช่ magic-link
5. **SPOF/push quota** — LINE surface เยอะ = จุดพังเยอะ → **กัน:** web fallback ครบ + health-check + throttle push + log delivery
