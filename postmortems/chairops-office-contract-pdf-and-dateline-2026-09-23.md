# Post-mortem: office contract view still had the old print button + missing date line; ID-card upload thumbnail not clickable anywhere

**Summary.** Two related follow-ups from the same-day ChairOps contract-PDF work, deployed together. (1) The ADMIN-facing contract view (`office-contract-view.tsx`) still used `window.print()` — the maid-facing fix earlier the same day (`380d7012`) only covered the maid's own contract page. CEO sent a screenshot of the print output showing the browser had stamped its own URL and timestamp onto the page, and a reference copy of the original paper contract showing a "ทำ ณ วันที่ ..." (made-on-date) line the digital version was missing. (2) Separately, the shared `IdCardUpload` component's existing-attachment thumbnail (used by the office contract editor, among 3 other places) was never clickable — same root cause as an earlier same-day fix (`82962209`) to the maid-detail page's read-only display, but a different component entirely. Branches `claude/chairops-contract-pdf-office-and-dateline-2026-09-23` + `claude/chairops-idcard-upload-clickable-2026-09-23`, merged onto `setup` at `fc2c8560`. **Deployed live 2026-09-23.**

**Symptom 1 (office PDF).** CEO: "เหมือนจะยังบันทึกไฟล์ PDF ไม่ได้ ได้แค่กดปริ้น แล้วเวลาไฟล์ออกมาหน้าตามันไม่เหมือนสัญญา เลยไม่สวยเลย จัดหน้าให้สวย เหมือนในที่แนบ" (still can't save as PDF, only print, and the output doesn't look like the contract — format it nicely like the attachment), with a screenshot of the printed output and the original paper contract PDF attached for comparison.

**Root cause 1.** `office-contract-view.tsx:38` still called `window.print()` directly — it was explicitly left unfixed during the earlier PDF work (`380d7012`) as "desktop-oriented, out of scope," reasoning that only applied while the office view was assumed to be used on a desktop browser. Testing showed otherwise: browsers commonly inject a default header/footer (source URL, page count, print timestamp) into printed pages unless the page explicitly suppresses it via `@page` print CSS — this app doesn't, so every printed contract carried the browser's own chrome, which read as unprofessional next to a real, generated document. Comparing against the CEO's attached original paper template also surfaced a second, independent gap: the on-screen/PDF contract never had a "ทำ ณ วันที่ ... เดือน ... พ.ศ. ..." line at all — not a regression, just never built.

**Fix 1.** Added `GET /api/chairops/maids/[userId]/contract/pdf` — admin-gated (`requireRole(ADMIN)`), mirrors the maid-facing route's data-loading logic exactly but looks the contract up by `userId` param instead of the caller's own session, and reuses the *same* `ContractPdfDocument` component built earlier the same day (zero new PDF-layout code). `office-contract-view.tsx`'s button now points a plain `<a download>` at it instead of calling `window.print()`. Added the missing date line to both `contract-document.tsx` (on-screen) and `contract-pdf-document.tsx` (PDF) — filled from `signature.signedAt` once signed (Thai Buddhist-calendar day/month/year, split into 3 blanks to match the paper template exactly), left as dotted blanks otherwise, matching the original template's unfilled state.

**Symptom 2 (ID-card thumbnail).** CEO, in a separate message: "ไฟล์เอกสารบัตรประชาชนมีรูปถ่ายเอกสารแนบที่แม่บ้านแนบมา เปิดดูในระบบหลังบ้าน[ไม่ได้]" (can't open the ID-card document photo the maid attached, in the back-office system) — confirmed via follow-up question that this was still broken, not a positive test result.

**Root cause 2.** The shared `components/chairops/id-card-upload.tsx` component's existing-attachment preview (`<img src={url} ... />`) was a plain, unlinked thumbnail — same bug class as the maid-detail page fix earlier the same day, but a structurally different component. This one is used in 4 places: maid onboarding, contract signing, the maid's own profile edit, and — the one relevant to "ระบบหลังบ้าน" (back-office system) — the office contract editor (`office-contract-editor.tsx`). Office staff reviewing a maid's ID card via the contract editor had no way to see it full-size.

**Fix 2.** Wrapped the thumbnail (and filename text) in `<a href={url} target="_blank" rel="noopener noreferrer">`, matching the same click-to-view convention used everywhere else this component appears now. One fix in the shared component covers all 4 usage sites.

**How they were found.** Symptom 1: read `office-contract-view.tsx` directly against the CEO's report, recognized `window.print()` immediately from the same-day precedent; the missing date-line gap was found only by reading the attached reference PDF side-by-side with the current output, not from the bug report text alone. Symptom 2: grepped for `IdCardUpload` usages against the CEO's mention of "ระบบหลังบ้าน" (back-office), found the office contract editor as the relevant usage site, then traced into the shared component to find the actual missing link.

**Validation.** `./node_modules/.bin/tsc --noEmit`: 0 errors (both branches, and again after merging both onto `setup`). `eslint` on every changed file: 0 errors (3 pre-existing-pattern warnings on react-pdf's `Image` component, same as the earlier PDF work). `next build`: succeeded (one retry needed on a transient local DNS resolver flake resolving `fonts.gstatic.com` — confirmed via `nslookup` against `8.8.8.8` succeeding while the local resolver returned SERVFAIL; self-healed within seconds, unrelated to any code change, and irrelevant to the actual Vercel production build which uses different infrastructure). Functional test with real production data: logged into a local dev server with the real test-admin account, navigated to the office contract view for a real signed contract, confirmed the button now says "ดาวน์โหลด PDF" with the correct href, then fetched the PDF directly through the authenticated session (200, ~4MB), converted every page to PNG, and visually confirmed the date line renders correctly (`ทำ ณ วันที่ 23 เดือน กันยายน พ.ศ. 2569`), the layout closely matches the CEO's attached paper template, and there is no browser-injected print header/footer anywhere in the output.
