# Post-mortem: ChairOps signed-contract "print/save PDF" button does nothing in LINE's in-app browser

**Summary.** `signed-contract-view.tsx`'s "พิมพ์ / บันทึก PDF" button called `window.print()` and relied on the browser's own print-to-PDF dialog. That API has no effect inside LINE's in-app browser (no print pipeline available there), so the button silently did nothing for the maid/broker who reported it — confirmed from the actual signed contract's `signedUserAgent` field, which contains `Line/26.15.0`. Replaced with a real server-generated PDF served from a new `GET /api/chairops/contract/pdf` route, linked via a plain `<a download>` — no client-side print API, no JS-driven fetch, works in any browser including restrictive in-app webviews. Bundled in the same change (same CEO request, same page): the maid's selfie (already captured at onboarding) now appears top-right on the contract, matching the standard Thai document convention, snapshotted onto the contract row at sign time. Branch `claude/chairops-contract-pdf-selfie-2026-09-23`, merged onto `setup` at `380d7012`. **Deployed live 2026-09-23.**

**Symptom.** CEO sent a screen recording of the "สัญญาเซ็นเรียบร้อยแล้ว ✓" page: "กด ออกมาเป็น PDF ไม่ได้ครับ" (pressing it doesn't produce a PDF), plus a request that the contract "look nice like the example I sent" and include the maid's selfie in the top-right corner, same request this session already had context for from the camera/upload fixes earlier the same day.

**Root cause.**
```tsx
// signed-contract-view.tsx (before)
<button type="button" onClick={() => window.print()}>
  <Printer className="size-4" /> พิมพ์ / บันทึก PDF
</button>
```
`window.print()` opens the browser's native print dialog, from which a user picks "Save as PDF." In-app webviews (LINE, Messenger, Instagram, etc.) commonly don't implement the browser's print pipeline at all, so the call is a silent no-op — no error, no console warning, just nothing happening. This was confirmed, not assumed: querying the actual signed contract row in production showed `signedUserAgent: "...Mobile/15E148 Safari Line/26.15.0"` — the `Line/26.15.0` suffix is LINE's in-app browser's own UA signature, proving the CEO's test session really was inside it. The identical button exists in the ADMIN-facing office view (`office-contract-view.tsx`) but was left untouched — that page is desktop-oriented, out of the reported scope, and flagged as a lower-priority follow-up.

**Why a real download instead of a client-side PDF library.** The repo already has a DOM-screenshot library (`@zumer/snapdom`, used by the "pinpoint" feature) that could have produced a PDF-like image for free, but its own code comments (`lib/pinpoint/capture.ts`) explicitly call it "unstable + heavy" on mobile/touch devices and skip it there — the exact device class this contract page runs on, and the same reliability theme as every other bug fixed in this repo today. A genuine PDF library was the safer choice. `@react-pdf/renderer` was picked because it builds a real vector PDF (selectable text, no canvas/GPU dependency) rather than screenshotting the page.

**Why server-side, not client-side.** `@react-pdf/renderer`'s browser build fetches remote images via `fetch()` (confirmed by reading `@react-pdf/image`'s source directly, not assumed). The contract's ID-card/selfie/signature images are served from R2's public `*.r2.dev` domain, which the site's CSP `connect-src` does not allowlist (only `*.r2.cloudflarestorage.com` is — see `lib/supabase/proxy.ts`), so a client-side render would have hit the exact same class of CSP block already fixed twice earlier the same day in the onboarding/signature upload paths. Rather than loosen a site-wide security header, generation moved server-side (`app/api/chairops/contract/pdf/route.ts`), where Node's `fetch()` has no CSP at all. This also keeps react-pdf's fairly large dependency tree out of the client bundle.

**Font gotcha (also confirmed by testing, not assumed).** Thai text needs a real font registered with `Font.register()`. The obvious first choice, `@fontsource/ibm-plex-sans-thai` (already a candidate since it's the app's own body font), only ships `.woff`/`.woff2` files — no `.ttf`/`.otf`. Registering the woff2 file produced a completely blank PDF page with no error at all; only rendering and visually inspecting the output (via `pdftoppm`) caught it, code review alone would have shipped this silently broken. Switched to a genuine TTF (IBM Plex Sans Thai, SIL Open Font License, pulled from Google's own font source repo), self-hosted under `public/fonts/` and fetched by the server at render time over plain HTTPS from the app's own domain (`NEXT_PUBLIC_APP_URL`) — chosen over `fs.readFileSync('public/...')` specifically to avoid unverifiable assumptions about whether Vercel's serverless function bundle includes arbitrary `public/` files at runtime.

**Fix.**
- `app/(admin)/chairops/(maid)/m/contract/contract-pdf-document.tsx` (new) — a parallel `@react-pdf/renderer` implementation of the on-screen contract layout (primitives, not DOM/CSS, so it can't share JSX with `contract-document.tsx` — kept in sync by hand).
- `app/api/chairops/contract/pdf/route.ts` (new) — auth-gated (`requireExactRole("MAID")`), loads the caller's own SIGNED contract, renders via `renderToBuffer`, returns `Content-Disposition: attachment`.
- `signed-contract-view.tsx` — button replaced with `<a href="/api/chairops/contract/pdf" download>`.
- `ChairopsMaidContract.selfieImageUrl` (new nullable column) — snapshotted server-side in `signContract()` from `ChairopsUser.selfieImageUrl` at the moment of signing (not trusted from client form data, matching how the company deposit account is already handled in that same function), and folded into the existing SHA-256 tamper-evidence hash (`lib/chairops/contract/hash.ts`) alongside `idCardImageUrl` so the newly-added legally-relevant field is covered by the same integrity guarantee.
- `contract-document.tsx` — top-right photo box added to the on-screen preview, same visual spot as the PDF.
- `app/(admin)/chairops/(office)/maids/[userId]/contract/page.tsx` — updated to pass the new field through (a second, pre-existing call site building the same `ContractDocData` shape, found via typecheck failure, not by grep alone).

**How it was found.** Read `signed-contract-view.tsx` directly against the CEO's complaint, recognized `window.print()` immediately given the same-day precedent of two other in-app-webview-specific bugs on this exact contract flow. Confirmed the actual browser (not assumed) by querying the live `signedUserAgent` on the real contract row. Confirmed the CSP-blocking mechanism by reading `@react-pdf/image`'s browser-build source rather than guessing. Confirmed the woff2 font failure and the eventual TTF fix by actually rendering PDFs and visually inspecting them (`pdftoppm`), twice — once with synthetic test text, once with the CEO's own real signed-contract data pulled read-only from production.

**Validation.** `./node_modules/.bin/tsc --noEmit`: 0 errors. `eslint` on every changed file: 0 errors (3 pre-existing-pattern `jsx-a11y/alt-text` warnings on react-pdf's `Image` component, which the linter can't distinguish from an HTML `<img>` — harmless, non-blocking). `next build`: succeeded, new route `/api/chairops/contract/pdf` present in output. Functional test with real production data: pulled the CEO's own actual signed contract (real ID card photo, real selfie, real signature, real content hash) via a read-only script, rendered it through both the new PDF route and the updated on-screen preview via temporary unauthenticated dev routes (`/api/dev-pdf-test-tmp`, `/dev-doc-test-tmp` — both deleted before merge, never shipped), converted the PDF to PNG per page and visually inspected: Thai text and tone marks render correctly, both photos and the signature embed correctly, the SHA-256 hash footer is intact, and (after one fix — `wrap={false}` on the sign-box row, which was originally splitting mid-box across the page boundary) pagination is clean. The on-screen preview's new photo box was also screenshotted at a 390px mobile viewport and confirmed to lay out correctly. Pre-push gate: `/verify` in full (typecheck, eslint, `next build`, clean `git status --porcelain`, live smoke test — `/`, `/login`, `/health`, `/chairops/m/contract` all healthy).
